The run before the outline pass was also in order: two intake rounds inside the cap of three and one full playback with no model. In all it stopped nine times before the board landed where the playbook budgets three.

**The defect is in the skill contract first and the scenario second. It is not the model.**

- **Contract.** The same section says two opposite things. Line 98 says each proposal waits for a yes. Line 111 says "An unanswered proposal never stops the run" and that "The playback before the gate names it". Section 8 puts the one full playback before the model, and the outline pass sits inside the Model step, so no playback comes after the pass to name an unanswered proposal. The model took the first sentence. Phase 034's run of the same scenario skipped the pass, so the ambiguity also produces run to run variance. Both sentences predate phase 035, so this is not a regression from it.
- **Scenario.** The three scripted turns and playbook Section 4 give the operator an answer for an intake round, the playback and the gate. They give none for an outline pass proposal. On a prompt that already settles every Brief row the pass is pure overhead against the budget the scenario sets.
- **Model.** Defensible. It did what the stricter sentence says and asked at each stop whether a yes would stand.

**Proposed amendment, not applied.** In `sk-create-figjam/references/flow-mode.md` line 98, replace "Each one waits for a yes, an edit or a skip." with "Each one is stated with its recommended answer and none stops the run." In line 111 replace "The playback before the gate names it" with "The gate names it". Until then, add to playbook Section 4 that each outline pass proposal is answered with "Yes, go ahead."
