## Connector crossings on the two architecture boards

Both boards cross a connector. On FJ-019 (88:2397) and FJ-024 (90:2398) the dashed Consumes edge out of the Change Stream drops down the gutter between the Events and Stores lanes and crosses the solid Writes edge from the service into the blocks database, right where that edge enters the database. The overlap reads as Consumes joining the database. The same edge also runs 19 px from two zone borders for about 165 px, which the phase 035 zone rule forbids.

The composer caused it. Phase 035 put Events (async) between Services and Stores, so the stream sits between the service and the store and the backward consume edge has to pass the service to store edge. The models drew only edges the architecture table allows (service to store, service to async, async to service). The check printed 0 crossing pairs on both because it does not see routed geometry. Compose-trace.mjs run offline on FJ-024's model with Push Worker declared first gave the same node coordinates as the original order, so the reply's own fix on FJ-024 (declare Push Worker first) would not move anything. That trace is an offline stand-in and the crossing itself is read from the screenshots. The FJ-019 reply understates it as 'run together for about 24 pixels'. The FJ-024 reply says it crosses.

A model-side dodge exists (draw the worker as producing into the stream) but reverses the stated direction, so it is not a fix.
