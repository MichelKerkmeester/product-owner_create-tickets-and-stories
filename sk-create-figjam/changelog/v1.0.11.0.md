# v1.0.11.0, Plans Follow the Board

Claude Sonnet 5.5 high reran on v1.0.10.0 the 6 scenarios that had failed and passed 2. The operator closed testing there, and this release fixes what the findings named, with no rerun.

## What's New at a Glance

- **A state board is planned as drawn.** The first state first, the states inside a composite second and the end states last, because the composer draws end states on the last ranks. A `%% focus:` line marks the named state where it is drawn, and that state leads its glance line
- **The main row is the drawn row.** On a user flow or a process the second glance is the longest path from the entry to the goal in path order, a detour on it included, and every node off it goes last. Two decisions no longer share a line
- **A boxed-in sticky goes to the gate.** When every side of a noted node is taken, the gate offers pins and a legend or a recompose, and a single sticky never sits more than one sticky width from its node. A sticky is a fixed 240 pixel square, and a size probe runs inside the notes call
- **One intake rule.** After accepted answers the next reply is the playback, or one round about a row the last round left open or a gap the answers opened
- **A revision reads first.** A revision playback reads the board with `get_figjam` first, and its read-back names the changed end as the second glance

## Changed

- The read-back counts connector labels from the write's return and the screenshot, because `get_figjam` returns none
- The user flow and process examples plan the main row as the composer draws it, and the state example plans its board as drawn with Cancelled leading the last glance line
- The style guide and the gate step name the first state as a state board's first glance
- The playbook scores a state board as drawn, gives the entry and the goal in one line no order, keeps content the file held before the write outside the glance order and never counts two runs FigJam draws closer than the composer's path estimate as a trunk
- Every board scenario allows the intake rounds a run opens, and each round moves the later turn numbers by one. Every scorecard Pass line also needs every expected signal
- FJ-031 expects the board read before the playback and the write time in the delete question
- FJ-017 lets its gate offer pins or a recompose when a noted node has no free side, and fails a sticky more than 240 pixels from its node or a size probe made as its own call
