# v1.0.12.0, Gate Sides and Goal Names

Claude Sonnet 5.5 high reran on v1.0.11.0 the 4 scenarios that had failed and passed 2. FJ-017 parked a sticky that had no free side, FJ-036 put its accent on the goal at the far end of the row and the findings named a gate that skipped its sketch, a stop that ended on a self-scan line and a label trace that missed a lone word. This release fixes each one.

## What's New at a Glance

- **The gate sees each note's side.** A model whose board carries single stickies names their nodes on a `%% notes: <id>, <id>` line, which moves the key down by one sticky and its gap. `flow_check.py <model> --notes <id>,<id>` composes the board in memory and prints a `Sides:` line per node, naming the side its sticky takes or saying the node is boxed in, and a sticky already placed takes its side from the next node. The gate names each side, or offers pins with a legend or a model change for a boxed-in node
- **The goal is named, not accented.** The composer draws the goal at the far end of the main row, where readers reach it last, so the goal never takes the accent. A `%% goal: <id>` line names it, and the one accent goes to a decision, a failure end or the one step in focus. The six user flow templates, two process templates and the Fernhouse return example now accent a decision or a step and name their goal
- **The gate shows its sketch.** The gate always shows the checked model with the check's result and answers four critique questions about it, unless the user already settled them: where the eye goes first, what it reads second, what a reader could miss and which node the remove test would cut next
- **A stop ends on its question.** An intake round, the playback and the gate deliver nothing, so none carries the `HVR self-scan:` line after its question

## Changed

- The check now fails a model the composer would refuse, such as a goal line naming a step, so the gate never shows `PASSED` for a board the write cannot make. A `--notes` id the board does not draw fails the check instead of reading as boxed in
- The sides check chooses the sides of all the noted nodes together, so one sticky gives up its first side when that leaves another node room, and the notes call places each sticky on the side its line named
- Every example gate shows its sketch and answers the four critique questions
- The label trace reads each label at both the normal and the narrow character measure, so a lone last word FigJam wraps, such as `tip`, prints a `Label:` line
- The check's no-accent message names a decision, a failing end or the one step in focus as the accent candidates
- The composer refuses a `%% goal:` line that names a node other than an end and a `%% notes:` line that names a missing node. The Project composer code is 47,612 characters with 2,406 left for the model
- The playbook reads a group the request names as one, such as the end states, as a set whose order no one scores, and fails a stop that ends on anything after its question or a gate with no sketch, check result or critique answers
- FJ-017 expects the `%% notes:` line, a `Sides:` line per noted node and each sticky on the side its line named. FJ-022 expects the confirmation named as the goal and the accent on the 30-day decision
- The playbook's Signal rule keeps an accent where the board put it and never on the goal
