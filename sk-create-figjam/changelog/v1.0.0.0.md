# v1.0.0.0, FigJam Diagrams as Their Own Packet

Flow Mode drew boards from inside the Product Owner packet, so every Product Owner reader carried FigJam rules it never used. It now has its own packet beside `sk-product-owner/` and `mcp-figma/`, and it draws every type Figma's `generate_diagram` supports rather than user flows alone.

## What's New at a Glance

- **Its own packet.** `references/flow-mode.md`, `assets/flow-templates.md`, `scripts/flow_check.py` and the vendored Mermaid extractor moved here. A new `SKILL.md`, which carries the packet's routing in its Section 2, a `README.md` and this changelog sit beside them
- **Seven diagram types.** User flow, process, architecture, sequence, state, ER and gantt, each with a reference under `references/types/`, a template under `assets/templates/` and a worked example under `assets/examples/`. `flow-mode.md` now picks the type from the reader's question and names the nearest drawable type for a kind the generator refuses
- **A check for every type.** `scripts/flow_check.py` dispatches each Mermaid block to a rule module under `scripts/figjam_checks/`, with its own parsers where the vendored extractor misreads a type. The self-test plants one defect per rule and checks every template and example
- **Style, quality and extensions.** `references/style-guide.md` records the FigJam palette with measured contrast, `references/quality-rubric.md` adds the judgment pass before the gate, and `references/hybrid-workflow.md` adds pins, stickies, tints and legends through `use_figma` after a write
- **Stage one routing.** The hub sends `$flow`, `$figjam` and a FigJam request with no other artifact to this packet, and the hub `ROUTER.md` maps the Flow intent to its pair. A Flow route that still reaches the Product Owner router hands off here
- **One copy of the voice cards.** The packet reads `hvr-core.md` and `conciseness.md` from `../sk-product-owner/references/`
- **A board beside an artifact.** A request for a Story, a task, a bug or a doc that also asks for a FigJam board now writes the artifact first and then runs Flow Mode from it under its own gate. A board whose read-back matched goes into the artifact's `Flows` group, or `Related references` for a Doc, and the artifact is saved again with it before ClickUp is offered. Sequencing words such as "then", "plus" and "and also" keep both outputs, and "write a doc" or "write a bug" now frames its artifact
- **A screenshot pass after the read-back.** It takes the screenshot from `get_figjam` first and looks for a cut label, connector crossings, an edge that seems to join the wrong node, a misplaced accent and whether the board answers the `userIntent` sentence. A finding is fixed by reshaping the model and regenerating after a yes. The accent node has to read first
- **Direction from the connector.** The read-back reads which way an arrow points from its endpoint ids and end caps, never from where it sits on the board, and a slow board is read again on half as many nodes. A connector with a missing end is named as dangling, and an ER connector is compared by its cardinality markers
- **Plans and tags.** A `whoami` tool, where the server has one, settles the plan of a new file before the gate, and a revision names its plan only when the user gave it. Created nodes may carry a tag as metadata, shared plugin data keyed by the diagram's name, so a later session replaces a diagram instead of drawing a second one
- **The accent and the cut.** The one accent sits on the node a reader would keep if they could keep only one, and a node that does not serve the `userIntent` sentence is cut and named under `Left out:`. A label repeated on four or more connectors is cut, or renamed per edge in an architecture, and the check script fails one on a user flow or a process
- **Hand edits.** A request to move, resize or restyle a generated node gets the edit to make in FigJam, and two failed attempts end with that offer
- **The hosted route.** `flow-mode.md` names the native MCP connection to `https://mcp.figma.com/mcp` and says Code Mode holds no manual for Figma's hosted server. The gate names the read calls a write spends, because a Starter plan or a View or Collab seat gets six tool calls a month
- **An intake that asks until it can draw.** A Brief of nine rows fills over interview rounds capped by energy, each question carrying the AI's reading and a recommended answer, and an unanswered question proceeds on that recommendation, marked assumed and named in the playback before the gate. An outline pass agrees the shape as text, a challenge ladder asks what the board must not do first, and a just-do-it request runs at Quick energy with every assumed row named
- **Input read by its evidence.** A Figma flow is read from its reaction graph first, an image label is read twice, the order comes from an inference ladder that asks only when every other signal is spent, and each item lands in a provenance row with its confidence and rung before any Mermaid. The chosen type is tested against what it needs, contradicted items surface under `Left out:` and the inferred rows are re-read before the gate
- **Design that plans the first glance.** Three glance lines travel into the gate, every diagram carries a title at 60 to 96 pixels, spacing follows three bands, a board of several diagrams reads as numbered zones, a legend keys every mark with a dashed tint and a reading distance dial trims nodes and labels. `scripts/figjam_checks/layout.py` measures the widest rank, the longest path, connectors per step, label length and crossings before the write

## Upgrade

The claude.ai Project keeps Flow Mode as a mode of its one kernel. Its Flow Knowledge files carry the new types as `../SYNC.md` records.
