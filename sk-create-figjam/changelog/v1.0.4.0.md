# v1.0.4.0, Dependencies, End Marks and a Delete That Names Its Boards

The three-model comparison in `benchmark/reports/2026-10-25--manual-testing-playbook--figjam-model-comparison/` recorded six findings. Every reader had to work out a gantt's dependencies from its dates, an ER line's direction from its label and a state's exit from a zone's edge. One model deleted ten boards on a generic yes, and another read a missing file key as an outage. This release fixes all six.

## What's New at a Glance

- **Gantt dependencies are arrows.** Each `after` draws one arrow from the end of the bar it names into the bar that waits on it, so what must finish first reads without the dates. A milestone's arrow leaves the bar's foot and meets the diamond's side
- **ER ends carry their cardinality.** Each relationship end takes Figma's crow's-foot mark, `ERD_EXACTLY_ONE`, `ERD_ZERO_OR_ONE`, `ERD_ZERO_OR_MORE` or `ERD_ONE_OR_MORE`, so a reader sees which side is the many. The label keeps both ends in words
- **A delete names its boards.** `references/flow-mode.md` Section 6 runs a delete only on a reply that names the boards it removes, or a yes to a question that names exactly those boards. A bare yes, the gate's yes and an answer to a question that named no board delete nothing. A board this conversation did not write is deleted only when the request is about it, never to tidy the page
- **A missing file key is not an outage.** Section 9 gains a recovery step: `use_figma` answers a call with no `fileKey` with "Failed to connect to MCP server 'figma'", so the model checks for the gate's key and retries once with it before it calls the route down

## Changed

- `references/types/state.md` now says a move that only one inner state takes names that state as its guard, such as `missed check-in [from Upcoming]`, because a transition from a composite leaves the zone's edge and reads as open from every state inside it. The Roamstay state example follows it
- The gantt model gives a task with `after` its list of ids, and `expect.connectors` counts them. The ER model gives each relationship `ends`, one character per end, in place of `undirected`
- The gantt and ER type references describe the arrows and the end marks, and their read-backs count them
- Every board-quality and board-creation scenario now passes only when every expected signal is present as well as the scorecard, as the root playbook's acceptance rules already said, and the root playbook Section 3 says so. FJ-027 expects the end marks and FJ-028 the dependency arrows
- `compose_board.py --self-test` proves each dependency is one arrow from the bar it waits on and each ER end carries the mark its model names, 1,029 checks in all
- The compact composer grew from 46,569 to 47,148 characters, so the model JSON and the `THEME` line have about 2,850 characters of room in one `use_figma` call, down from about 3,400. The largest shipped example model runs about 2,300
- The gallery's process image is SWE 2 Max's FJ-023 board, which carries the accent on the step the request named, after the comparison's gallery rule moved to rank the board points first
- The gallery's gantt, ER, existing-board and dense-flow images were drawn again from their best run's model with this composer. The gantt and ER images now show the arrows and the end marks, and the other two the design file. The dense flow's model took the two changes today's check asks for, one accent and a shorter credit label
