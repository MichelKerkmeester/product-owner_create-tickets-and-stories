# v1.0.2.0, Board Gallery and Second Glance

The 2026-10-25 playbook run graded every diagram type on a composed board, and nine of those boards now sit in the packet as the first thing a reader sees. The same run left one board at Composition 1 because the gate planned the wrong second glance, and the rubric now says how to plan it.

## What's New at a Glance

- **A gallery.** `assets/screenshots/` holds nine overview renders of boards the skill composed on a fictional test file: user flow, process, architecture, sequence, state, ER and gantt, a state diagram written onto a board that already held content and a user flow at the nine-node budget. `README.md` Section 2 shows each one with a caption on what to notice, and `assets/screenshots/README.md` names the playbook scenario and scorecard result behind it, 19 to 22 of 22
- **The second glance.** `references/quality-rubric.md` says filled shapes outweigh connector labels once the first glance has landed, so the gate plans a filled shape second
- **Readable state names.** `references/types/state.md` gives a multi-word state its readable name as a description, so a board shows In stay where the request said In stay
- **The read-back.** `references/flow-mode.md` Section 7 reads the nodes already on the file again after the write, and a request to use the recommended answers after the playback counts as the playback's answer

## Changed

- `compose_board.py`, `flow_check.py`, `compose-board.js`, `compose-trace.mjs` and the `figjam_checks` modules carry file headers, numbered sections, docstrings and type hints. The composer's output is unchanged, and its mirror in the Project still equals `compose_board.py --template` byte for byte
- `flow_check.py --self-test` skips a folder README under `assets/`, which describes files rather than modelling a diagram
- Two playbook scenarios, FJ-027 and FJ-032, match the changed rubric

## Upgrade

In the claude.ai Project, replace Rules - Flow Quality Rubric, Templates - Flow Mode and Templates - Flow Type - State. The gallery and the code comments need no Project change.
