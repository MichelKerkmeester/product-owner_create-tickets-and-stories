## 2. CRITERIA

One row per criterion. `AC-ID` is stable once written: supersede a criterion, never renumber it.

| AC-ID | REQ | Given / When / Then | Verification | Status | Waiver |
|-------|-----|---------------------|--------------|--------|--------|
| AC-001 | REQ-001 | Given the audit, When every finding is fixed, Then a re-audit finds none | Audit findings fixed or shown not to hold, report in the session scratchpad | Met | - |
| AC-002 | REQ-002 | Given a mode request in a Project, When the kernel routes it, Then the named Knowledge files exist and hold the mode | Kernel routes checked against the Knowledge names by the audit, every cited name resolves | Met | - |
| AC-003 | REQ-003 | Given the scratch clone, When validate_parity.py runs, Then it reports zero findings | validate_parity.py passed 64 of 64 in the scratch clone | Met | - |

### Status values

| Value | Meaning |
|-------|---------|
| `Met` | Verified. The Verification cell names evidence that was actually observed. |
| `Unmet` | Not yet satisfied. Blocks closure. |
| `Waived` | Deliberately not pursued. Requires an ADR in the Waiver cell. |
| `Superseded` | Replaced by a different criterion or decision. Requires an ADR in the Waiver cell. |

### Waiver cell

Write `-` when the row is `Met` or `Unmet`. Write `ADR-NNN` when the row is
`Waived` or `Superseded`, naming a decision record that exists in
`decision-record.md`. A waiver naming an ADR that is not there fails validation:
the point of a waiver is that someone recorded the reasoning, so an unbacked
waiver is treated as an unmet criterion rather than as a pass.
