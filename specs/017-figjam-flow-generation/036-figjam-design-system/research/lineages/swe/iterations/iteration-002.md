## Findings

1. The public convention this question borrows already exists and is stable: Google Labs' `DESIGN.md` format pairs a machine-readable YAML token layer (front matter or interleaved fenced blocks, normative values) with human-readable markdown rationale, is positioned as "the design counterpart to `AGENTS.md`", accepts unknown sections and custom tokens, and is published as `@google/design.md` (~208k weekly npm downloads) — a repository user can edit it, and an agent or a script can parse it. [SOURCE: https://github.com/google-labs-code/design.md/ ; https://cdn.jsdelivr.net/gh/google-labs-code/design.md@main/docs/spec.md ; https://www.npmjs.com/package/@google/design.md]
2. The mature interchange model underneath is the W3C Design Tokens Community Group Format Module, which reached its first stable version (2025.10, 28 Oct 2025): typed tokens via `$type`, named groups, `{path.to.token}` aliases, and theming — a board spec should borrow its typed groups and alias syntax inside a markdown/YAML envelope rather than adopt raw DTCG JSON, which is built for tool interchange, not hand-editing. [SOURCE: https://www.w3.org/community/design-tokens/ ; https://www.designtokens.org/tr/third-editors-draft/format/]
3. The repository's own precedent, `sk-design-md-generator`, produces a v3 Style Reference whose cardinal rules translate directly: every value verbatim from a single token source, named semantic roles over raw values, no false systems, and a validator that checks hex accuracy and section completeness — for this packet the "measured source" already exists (the composer constants), so the spec file records them verbatim with rationale rather than extracting anything. [SOURCE: .skilled/skills/sk-design/sk-design-md-generator/references/design-md-format.md:28-46; .skilled/skills/sk-design/sk-design-md-generator/references/design-md-format.md:311-356]
4. The md-generator's authoring boundary clarifies scope: it captures measured reality and refuses forward-authoring — a FigJam board spec is *authored defaults*, which is exactly the gap the boundary leaves open, so the packet would own a hand-authored spec (with the current constants as its verbatim baseline), not an extraction. [SOURCE: .skilled/skills/sk-design/sk-design-md-generator/SKILL.md:14; .skilled/skills/sk-design/sk-design-md-generator/SKILL.md:44-48]
5. Consumption is mechanically trivial: `compose_board.py` already builds the use_figma payload by substituting `__MODEL__` into the template under a 50,000-character ceiling — a spec rides the same path as a second injected block (e.g. `__STYLE__` resolved to a frozen constants object), adding zero runtime calls and keeping "one use_figma call per board" intact. [SOURCE: AI Systems/Product Owner/sk-create-figjam/scripts/compose_board.py:70-76; AI Systems/Product Owner/sk-create-figjam/scripts/compose_board.py:595-596]
6. The spec's real job is ending a three-way split of the same palette truth: `compose-board.js` draws it, `figjam_checks/common.py`'s `ACCENT_PAIRS`/`PAIRED_FILL`/`LANE_PAIR` accepts it, and the claude.ai Project knowledge file copies the composer — today three artifacts must agree by convention; a spec file becomes the single source the first two are validated against, while the mirror (which has no Python and fills MODEL by hand) ships the resolved constants inside its copied code rather than reading the file at runtime. [SOURCE: AI Systems/Product Owner/sk-create-figjam/scripts/figjam_checks/common.py:47-63; AI Systems/Product Owner/sk-create-figjam/scripts/compose_board.py:71-73]
7. The packet already treats the composer source as a de facto spec: `compose_board.py`'s self-test regex-parses `SHAPE_PAIR`/`KIND_PAIR` out of `compose-board.js` to re-derive every pair and assert the accent's hue separation (≥45°) and mark gate (≥3:1) — a declared spec file replaces fragile source-parsing with a normative token surface, and the existing checks become its validator. [SOURCE: AI Systems/Product Owner/sk-create-figjam/scripts/compose_board.py:700-727]
8. The validation machinery a spec needs is already owned, not borrowed: `contrast()` computes WCAG ratios, `hue_of()` measures hue separation, `MIN_HUE_APART = 45` and the 4.5:1 text / 3.0:1 mark gates are constants — spec validation is a thin layer that re-runs these against user-edited tokens. [SOURCE: AI Systems/Product Owner/sk-create-figjam/scripts/figjam_checks/common.py:157-158; AI Systems/Product Owner/sk-create-figjam/scripts/compose_board.py:702-726; AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:170-174]
9. Deepens iteration 1 finding 15: the type references confirm divergence is kind vocabulary, not style — sequence colours messages by arrow kind and adds numbered pins (a sequence takes no zone line), state colours first/final states and pseudo-states by role with composites as zones, so the shared invariant is the furniture+palette-grammar layer and the right spec surface is *per-kind tokens shared across types*, not per-type themes. [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/types/sequence.md:54-90; AI Systems/Product Owner/sk-create-figjam/references/types/state.md:54-90]
10. Safe defaults follow the packet's own philosophy: model errors refuse, style degrades gracefully — every spec key optional with the current constant as its default, an unparseable file warns and falls back wholesale, a token failing a floor (text < 4.5:1, mark < 3.0:1, accent < 45° apart, a non-pair colour) is rejected to its default rather than failing the board, matching how recorded departures are handled today. [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:176-185; AI Systems/Product Owner/sk-create-figjam/scripts/figjam_checks/common.py:13-16]
11. Location: packet level, not repository level — the spec describes one packet's drawing surface, a repo-root `DESIGN.md` would collide with `sk-design`'s artifact name and overreach; the natural home is a new file under `AI Systems/Product Owner/sk-create-figjam/` (e.g. `references/board-style.md` or packet-root `DESIGN.md`), with an optional user override file found by walking up from the model file, and the mirror keeps its own knowledge copy via the SYNC.md mirroring contract. [SOURCE: AI Systems/Product Owner/sk-create-figjam/SKILL.md:240-242; .skilled/skills/sk-design/sk-design-md-generator/references/design-md-format.md:49-64]
12. Rubric integration is a wording change, not a rewrite: Section 7's "Colour by meaning" and "Key and source" criteria already say "every colour names a kind the key explains" — under a spec, both score against the loaded spec's kind table instead of the hardcoded one, so the scorecard semantics survive and a spec conformance line joins the finding format. [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/quality-rubric.md:132-137]
13. The spec must draw a hard boundary around non-token concerns — the routing solver's cost constants, layout algorithm, key membership generation and the judgment bands stay out of the file, because exposing them invites boards that violate the solver's invariants and the spacing doctrine a user cannot see. [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:600-840; AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:221-234]
14. The deciding trade-off is FigJam recolourability: any spec colour outside the native swatch pairs silently breaks picker-recolouring on the board, so the spec should key colours by semantic pair (fill+stroke+text) and warn when a user value isn't a FigJam-native pair — preserving the property that made the packet refuse brand palettes is the cost a spec pays for user theming. [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:28; AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:156; AI Systems/Product Owner/sk-create-figjam/scripts/figjam_checks/common.py:43-46]
15. Schema shape (what the spec carries, each section defaulting to today's constants): `colors.pairs` name→{fill,stroke,text} and `colors.kinds` kind→pair; `accent` {pair, nodeWeight 8, messageWeight 4}; `zones` {tints, cycle order, label type}; `type` {family Inter, role→size/weight ramp}; `spacing` {grid 8, cross 80, rank 136, zone pad/head/gap, board pad, key offset}; `shapes` kind→FigJam shape + corner radius; `connectors` {color, weight 2, dash, caps, label type}; `key`/`title`/`subtitle`/`source` {fill, type roles, margins} — every section optional, whole-file fallback on parse failure. [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:27-97; AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:210-240; AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:1123-1202]
