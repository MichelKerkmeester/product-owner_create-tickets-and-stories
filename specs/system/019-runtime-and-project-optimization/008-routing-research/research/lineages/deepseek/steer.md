# Steer: Product Owner routing research

Rulings from the lead. They bind inside this lineage.

1. The research target is `AI Systems/Product Owner/` as ../../../spec.md scopes it, not the staging spec itself.
2. Read only. Never edit, create or delete a file outside this lineage directory, and run no command that writes elsewhere.
3. One question per iteration, in order: iteration 1 answers question 1, iteration 2 question 2, and so on to iteration 10, the synthesis. An iteration may close a gap an earlier one left, and says so.
4. Out of scope: Product Owner `specs/`, `export/`, `benchmark/reports/`, the vendored `mcp-click-up/`, `mcp-figma/` and `mcp-code-mode/`, and `AI Systems/Product Context`, any screenshot and any figma.com URL, which you never open.
5. Every finding cites [SOURCE: path:line] with a repository-relative path that resolves, and names the file a fix would change. Rank each P0, P1 or P2.
6. Before calling a file dead, search the whole Product Owner tree for its name and its stem, including JSON, shell and Python, and say what you searched. Before calling a README claim stale, open the file or count it claims.
7. When the repository cannot settle a question, record it as an open question, not as a fact.
