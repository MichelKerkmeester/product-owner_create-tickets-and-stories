## Findings

1. The repository's DESIGN.md Style Reference is a two-layer file: prose sections a person reads, plus one machine-readable `design-tokens` JSON block a tool reads. The extract "produces a `DESIGN.md` with 11 sections, including a machine-readable `design-tokens` JSON block" [SOURCE: AI Systems/Product Owner/mcp-figma/feature-catalog/design-system-extract-and-import/design-system-extract-and-import.md:27], and the generator's output is "a measured Style Reference (extracted design tokens)" [SOURCE: AI Systems/Product Owner/mcp-figma/SKILL.md:42]. That shape fits the FigJam need exactly: the prose carries the why (colour by meaning, one accent, the key names every mark) that the style guide already writes well, and the JSON block carries the values `compose_board.py` resolves.
2. The Style Reference is "measured", meaning each value is backed by a recorded measurement [SOURCE: AI Systems/Product Owner/mcp-figma/SKILL.md:52]. The FigJam style guide already works this way, with a measured contrast column per pair that the self-test re-measures [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:105-120]. The design spec should keep that property: every colour token gets its measured ratios written by the tool, never typed by the user, so a user edit is re-measured on every compose.
3. The same repository's import path already accepts "a W3C / Style-Dictionary `tokens.json`" and a `designmd` source [SOURCE: AI Systems/Product Owner/mcp-figma/feature-catalog/design-system-extract-and-import/design-system-extract-and-import.md:31]. Writing the FigJam token block in the W3C Design Tokens Community Group shape (each token an object with `$value`, `$type` and optional `$description`, groups as nested objects, aliases as `{group.token}`) **(format facts not fetched in this session)** keeps it importable by tooling the repo already uses, and lets a role alias a swatch (`"$value": "{swatch.lightGreen}"`) rather than repeat a hex, which is how "pick a FigJam swatch by name" from iteration 2 finding 6 is expressed.
4. A FigJam design spec must express roles, not raw paint, because the composer's colours are meaning: "A kind fixes shape and colour together, so a colour means the same thing on every board" [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:50]. The schema's colour layer is therefore three tiers: swatches (FigJam's named pairs, fixed), roles (entry, neutral, goal, exit, error, decision, store, io, external, accent, ink, line) aliasing swatches, and kinds (start, firstState, participant ...) aliasing roles. A user restyles by remapping a role; a kind-to-role mapping change is a structural edit the validator checks for distinctness. This fixes iteration 1 finding 2 at the source: today five kinds alias the same swatch with no shared role [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:52] [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:77].
5. Gantt reuses the positional tint cycle for its section bands [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:1087], so `gantt-board.png` shows blue, orange and teal sections that mean nothing, around white, light gray, light blue and light red bars that do. With the pink entry the fifth section of a longer chart would be pink beside a pink-outlined focus task. Deepens iteration 1 findings 1 and 3: the tint rule must be one spec token shared by graph zones and gantt sections.
6. Gantt sets its own sizes outside the type scale: bar label 14 px [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:1101-1102], row 56, bar 32, head 72 [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:1031], and the sequence pin text 14 px with row 72 [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:957] [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:1008]. The shared `TYPE` table [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:90] has no `small` step, so these live as magic numbers. Visible on `gantt-board.png`: "1 week, critical" inside the bar is the smallest text on the board. A spec needs a `type.small` token and per-type `rhythm` tokens (row height, bar height) so the scale is one table.
7. The sequence step pin hard-codes the violet pair [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:1009-1012], the same violet a data store draws [SOURCE: AI Systems/Product Owner/sk-create-figjam/assets/compose-board.js:61] and the note-pin preset uses [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:162]. The pin colour was chosen for its 4.57:1 white digit [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:174], a good reason to keep, but the spec should name it as its own role (`marker`) so a user who remaps `store` does not silently recolour pins, and the validator can keep the white-digit floor on `marker` alone.
8. Phase decision D1 freezes this as findings only, with no source, mirror or kernel change [SOURCE: AI Systems/Product Owner/specs/017-figjam-flow-generation/036-figjam-design-system/goal.md:44], and D5 fixes the model as the DESIGN.md Style Reference [SOURCE: AI Systems/Product Owner/specs/017-figjam-flow-generation/036-figjam-design-system/goal.md:48]. Every change below is a proposal, and the spec file recommended in the synthesis follows the two-layer Style Reference shape from finding 1.
9. Safe defaults need three layers, each tied to an existing check rather than new measuring code (deepens iteration 2 finding 10): (a) schema, unknown keys and wrong types fall back per token to the default with a warning; (b) floors, re-run `contrast` for text on every fill at 4.5:1 [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:172], the accent stroke at 3:1 and 45 degrees from every kind [SOURCE: AI Systems/Product Owner/sk-create-figjam/scripts/compose_board.py:702-727], now also from every tint, and the accent weight above every other mark [SOURCE: AI Systems/Product Owner/sk-create-figjam/references/style-guide.md:140]; (c) a failing role reverts to its default role while the rest of the theme stands, and the `COMPOSED` line and the reply's `Finding:` line name each reverted token. A theme can therefore never ship a board that fails the greyscale or first-glance rules the scorecard grades [SOURCE: AI Systems/Product Owner/sk-create-figjam/manual-testing-playbook/manual-testing-playbook.md:92].
