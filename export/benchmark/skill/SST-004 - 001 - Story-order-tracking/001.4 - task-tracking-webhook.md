# BE - TRACK - Tracking webhook and status mapping

### About

---

Receive the parcel carrier's `tracking.updated` events, store them per parcel and map codes to customer statuses for the web, iOS and Android timelines. `Packed` is out of scope, because orders-service already receives it from the warehouse system.

Every delivery must be accepted and kept, because `GET /v1/shipments/{shipment_id}` returns label fields only and tracking history is not in the carrier plan.

### Requirements

---

1.  **Receive tracking events**

---

One event per parcel scan, with the label webhooks' delivery rules, on a separate path because each subscription has its own secret.

**Checklist**

- [ ] Events arrive at `/webhooks/carrier/tracking` on shipping-service
- [ ] Requests are verified against `X-Carrier-Signature`, the hex HMAC-SHA256 of the raw body keyed with the tracking secret
- [ ] A 2xx returns within `5 seconds`, else up to `5 attempts` follow at `1 min, 5 min, 15 min, 1 h, 6 h`
- [ ] Deduplicate on `event_id`, stable across retries
- [ ] Each event stores `event_id`, `shipment_id`, `tracking_number`, `status_code`, `occurred_at`, `sent_at`, `eta_window` and `location`
- [ ] Intake handles about `43,000` events a peak day, up to `5,400` parcels at `5 to 8` each

---

2.  **Map carrier codes to customer statuses**

---

The order page shows Fernhouse statuses, never carrier codes.

**Checklist**

- [ ] `PU` and `IT` map to `Shipped`
- [ ] `OD` maps to `Out for delivery`
- [ ] `DL` maps to `Delivered`
- [ ] `EX` maps to `Delivery failed`, with no `exception_code` on the order page
- [ ] A new `OD` after an `EX` moves back to `Out for delivery`

---

3.  **Order by scan time**

---

Batched hub scans can land an `IT` after the parcel's `OD`, on busy days by over an hour, and retries arrive late.

**Checklist**

- [ ] Events are ordered by `occurred_at`, never by arrival
- [ ] An event older than the parcel's newest `occurred_at` is stored but does not change the status
- [ ] The current `eta_window` is the newest by `occurred_at`
- [ ] No `eta_window` on any event means no estimate, never one derived from the dispatch date

---

4.  **Keep tracking for 90 days after delivery**

---

**Checklist**

- [ ] Events are kept `90 days` after delivery
- [ ] Then the order page gets the last status only
