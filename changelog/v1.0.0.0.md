# v1.0.0.0, The Product Owner Hub

The Product Owner system was one skill that wrote backlog artifacts. It is now a parent hub with one advisor identity, `product-owner`, over four packets, built on the same contract as the skilled hubs.

## What's New at a Glance

- **Four packets.** `sk-product-owner` writes tasks, bugs, Stories, Epics and docs and is the default. `sk-create-figjam` draws FigJam diagrams, from user flows to sequence, state, ER and gantt charts. `mcp-click-up` and `mcp-figma` are byte copies of the shared ClickUp and Figma skills, kept in step by `scripts/vendor-sync.py`.
- **Two-stage routing.** `hub-router.json` picks the mode from `$` commands, opening signals, artifact words and negations, and the root `ROUTER.md` maps the request's intent to the leaves that mode loads. Each workflow packet routes inside its own `SKILL.md` Section 2.
- **A board beside an artifact.** A request for an artifact that also asks for a FigJam board stays with `sk-product-owner`, which writes the artifact first and hands off to `sk-create-figjam`. `hub-router.json` and `ROUTER.md` record that the pair forms in stage two with the artifact first, and four gold rows in `benchmark/hub-routing-cases.json` hold it for a Story, a runbook, a Doc and a Bug.
- **One identity.** Only the hub carries `graph-metadata.json` and `description.json`, and `leaf-manifest.json` is generated from the registry.
- **The repository root is the hub.** The `repo-root-hub` extension in `mode-registry.json` lists the repository's own entries, such as the specs, the exports and the Claude Project package. The skilled checkers skip them and read the hub id `product-owner` from the folder name `Product Owner`.
- **A board intake on both sides.** The Product Owner packet's Interactive Mode counts a board intake short of Flow Mode's draw-ready threshold as the one legal second round, reads just-do-it wording as Quick energy, and states the AI's reading and a recommended answer in every question, so an unanswered one proceeds on that recommendation and is named as assumed. The hub `ROUTER.md` notes that `flow-mode.md` Section 4 carries the intake rounds
- **Local ClickUp push targets.** `.env.example` lists one ClickUp link per artifact kind, and a gitignored `.env` or the shell holds the values, so the public repository never carries them.
