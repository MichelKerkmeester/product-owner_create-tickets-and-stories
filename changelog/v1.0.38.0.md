# v1.0.38.0, The Browser Hub Replaces the Two Browser Packets

Skilled moved its Aside and Chrome DevTools packets into one `mcp-browser-use` hub. Product Owner now vendors that hub, so the browser names in the ClickUp page routines point at folders this repository holds.

## What's New at a Glance

- **One browser hub.** `mcp-browser-use/` holds the Aside, Chrome DevTools and Bladebro modes, and it replaces the `mcp-aside-devtools/` and `mcp-chrome-devtools/` root folders
- **Current ClickUp packet.** `mcp-click-up` now names its browsers as `mcp-browser-use/mcp-aside-devtools` and `mcp-browser-use/mcp-chrome-devtools`
- **Update from GitHub.** `bash scripts/update-vendored.sh` brings every vendored skill in step with Skilled and runs the gates, with no local Skilled checkout needed
- **Add a skill by path.** `python3 scripts/vendor-sync.py add --package NAME --upstream .skilled/skills/...` vendors a new skill, mode or hub
- **No new mode.** The hub is a repository path like `mcp-code-mode`, and Bladebro has no manual registered here
- **Design briefings.** `sk-product-owner` v1.2.22.0 adds a Design Briefing task shape for the Product Design team, and a request to write one routes to Task Mode

## Changed

- `vendor.json` lists six packages. The hub entry leaves out `graph-metadata.json`, so the advisor still finds one `product-owner` identity
- `mcp-click-up`, `mcp-figma` and `mcp-code-mode` are in step with Skilled
- `vendor-sync.py` gains `--remote` and `--ref`, the `add` command and a rebuild line when a vendored server's source changes, and `/vendor-update` runs the update for Claude Code
- `mode-registry.json`, the hub `SKILL.md`, `README.md` and `scripts/README.md` name the hub where they named the two packets

## Upgrade

The browser hub changes nothing in the claude.ai Project, because no kernel or knowledge file names the browser packets. The Design Briefing does: replace the kernel, now v1.2.24, and the knowledge files that `sk-product-owner/changelog/v1.2.22.0.md` lists.
