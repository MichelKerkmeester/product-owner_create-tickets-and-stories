# v1.0.1.0, No Claude Code Plugin and Composed Boards

Product Owner ran in three places: the claude.ai Project, a terminal agent opening the repository and a Claude Code plugin built from the repository. Nobody installed the plugin, and keeping it fresh cost a gate on every change. It is gone, and the Project and the repository are the two supported ways to run the system. The same release changes how Flow Mode writes a board: it composes the board itself rather than handing Mermaid to Figma's generator, as `sk-create-figjam/changelog/v1.0.1.0.md` sets out.

## What's New at a Glance

- **No plugin folder:** `claude-plugin/`, its two manifests and the generated `skills/` tree are deleted
- **No build script:** `scripts/build-plugin.py` is deleted with its self-test
- **Gates:** the plugin freshness gate is gone and a board composer self-test is new, so `benchmark/gates/run_gates.sh` runs 15 gates, or prints `11 of 15 gates pass, 4 skipped` in a clone with no shared skill folder
- **Composed boards:** `sk-create-figjam` moves to v1.0.1.0. One `use_figma` call per diagram draws a framed board from the checked model, and `generate_diagram` becomes the fallback
- **A composer in the Project:** the new Knowledge file `Product Owner - Assets - Flow Board Composer` carries the composer's code and a guide to filling its model by hand, and the kernel's Flow write and Knowledge index name it

## Changed

- `mode-registry.json` no longer lists `claude-plugin` among the repository paths the skilled checkers skip
- `SKILL.md`, `README.md`, `scripts/README.md` and `benchmark/gates/README.md` no longer describe the plugin, its build or its gate
- `benchmark/gates/check_markdown_links.py` no longer skips a generated plugin copy, because there is none

## Upgrade

A clone that still holds an old `claude-plugin/skills/` folder can delete it. Nothing in the repository reads it.
