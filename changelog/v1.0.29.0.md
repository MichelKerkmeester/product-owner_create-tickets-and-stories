# v1.0.29.0, Whole-System Review Fixes and One-Command Vendor Sync

A ten-iteration review read the whole system and its nested skills. This release fixes what it confirmed.

## What's New at a Glance

- **Browser captures stay out of the repository.** The vendored browser packets carry a capture rule. `.gitignore` ignores HAR files and cookie dumps
- **One command syncs the vendored skills.** `vendor-sync.py sync` pulls every entry that is behind. It leaves the rest alone
- **A clone can check its vendored copies.** `status --local` reads no upstream. The release gate runs it where it used to skip
- **A dry look before a pull.** `diff` prints what differs from upstream and writes nothing
- **Every Mark-as-done line turns gray.** `mcp-click-up` v1.2.21.0 grays it whatever follows the words
- **The hub rules match the packets.** Each packet owns a `ROUTER.md`. The hub names the Chrome manual it registers
- **The format harness checks its twin.** `run_fixtures.sh` runs reference parity when the Sync Loop is present
- **The kernel names feedback tickets.** Kernel v1.2.19 adds their export path and counts thirty examples

## Changed

- The Project kernel moves to v1.2.19. `sk-product-owner` stays at v1.2.16.0
- `vendor.json` pins `mcp-chrome-devtools` v1.0.24.0, `mcp-aside-devtools` v1.1.10.0 and `mcp-click-up` v1.2.21.0
- `mcp-code-mode` is pulled to upstream, which raises its Node floor to 24.22.1
- `scripts/vendor-sync.py`, its tests and `scripts/README.md`
- The gate and fixture scripts under `benchmark/` and their READMEs
- Hub `SKILL.md`, `ROUTER.md` and `mode-registry.json`
