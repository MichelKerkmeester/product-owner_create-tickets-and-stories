# v1.0.5.0, Smaller FigJam Calls and Stops That End the Turn

A run of 24 FigJam scenarios on Claude Opus 5.5 medium found five things to fix in the skill and three in the test driver. `sk-create-figjam` v1.0.5.0 fixes the five.

## What's New at a Glance

- **More room for the model.** A FigJam call now carries only the builder its type needs, so a graph model has about 9,670 characters of room and a sequence or gantt model about 33,000
- **A named file is a valid target.** A board can go into an existing FigJam file the user names, beside what it already holds
- **Every stop ends its turn.** The playback and the gate are always the last message of their turn
- **No file outlives the write.** The scratch folder the check and the composer use is deleted before the reply

## Changed

- The comparison's driver sends a follow-up yes only to a scenario whose script answers the write gate, so a scenario that grades an earlier stop is no longer pushed past it
- The driver runs a scenario written for a runtime with no hosted Figma server on Claude Code with that server left out, and skips it on Codex, which reaches Figma through the account's app
- The README's FigJam section now says the playback and the gate each end their turn, a named FigJam file takes the board beside what it holds and a revision deletes the old board only on a yes to a question that names it. The templates table names the notes-on-a-board workflow

## Upgrade

In the claude.ai Project, replace the two Flow Knowledge files the `sk-create-figjam` v1.0.5.0 notes list. Paste kernel v1.2.6, whose Flow write bullet names a FigJam file the user named as a target and whose replay sentence says the replay and the gate each end their turn.
