# v1.13.0.0, Source Wording Stays as Written

A supplied value, name or status now travels into a task as the source writes it. A Behavior reference keeps its `## Behavior rules` heading, a backticked source phrase stays word for word in a Doc and an open question the source words itself stays quoted in a Story. The Project kernel stays at v1.16.0, since every rule lives in a document the kernel already routes to.

## Why This Release

After the first remeasure round, rows still dropped or reworded a supplied value. Task Mode had no rule that a supplied value travels into a task unchanged, since every such rule was written for a Story, so `HMAC-SHA256`, the status word `deprecated` and the service `booking-service` came and went between runs. Doc Templates never said the Behavior reference keeps `## Behavior rules` as its primary body heading and never said a backticked rule phrase such as `one discount code per order` is literal copy. Story Mode told the runtime to rewrite source prose and named no exception for an open question, so every run reworded `Do sub-pages inherit the link?`.

## What's New at a Glance

- **A supplied value, name or status travels into a task as the source writes it.** On the Core Rules line that already preserves source structure, a value a requirement builds or checks, an event, property or service name and a status word such as `deprecated` or `proposed` travel as the source writes them, inside backticks. A supplied value is a constraint rather than HOW, a status keeps its word beside its meaning, no generic stand-in replaces a named service and the Content Validation line asks for it.
- **A Behavior reference keeps its Behavior rules heading.** `## Behavior rules` stays its primary body heading and the subject's wording goes in the H3 headings beneath it.
- **A backticked source phrase stays word for word in a Doc.** A phrase the source sets in backticks appears word for word in the sentence that states its rule.
- **An open question the source words itself stays quoted in the Story.** The `**Open:**` line quotes it and then names who settles it.
- **The playbook root grades a backticked Pass-clause value word for word.** It does so where the source sets the value in backticks, gives it as a defined label or the clause says verbatim. It accepts the same value in other words elsewhere.
- **The long integration task accepts the board in the reply.** It no longer demands the carrier's retry count and schedule word for word.
- **The Android subtask lists `99` as it lists `365`.** The proposal accepts the current mechanism restated.
- **The mode pairs, scenarios, playbook and skill move to new versions.** The Task Mode pair moves to v0.306, Doc Templates to v0.108 and Story Mode to v0.404, with each Project mirror renamed and every live reference repointed. The playbook root moves to 2.2.0.0, the three edited scenario pairs move to 1.1.0.0, the Project scenarios whose links were repointed move by a patch step, `SKILL.md` moves from 1.12.0 to 1.13.0 and `description.json` moves from 1.12.0.0 to 1.13.0.0.

## Upgrade

No migration required. The Project kernel stays at v1.16.0, since every rule lives in a document the kernel already routes to. Its review by the operator is pending.
