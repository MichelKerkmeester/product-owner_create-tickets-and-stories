## [**1.13.0.0**] - 2026-09-26

A supplied value, name or status travels into a task as the source writes it, a Behavior reference keeps its `## Behavior rules` heading, a backticked source phrase stays word for word in a Doc, and an open question the source words itself is quoted in a Story's `**Open:**` line. These are rule changes, so the skill moves to 1.13.0. The Project kernel stays at v1.16.0, since every rule lives in a document the kernel already routes to.

> Scope: the Task Mode, Doc Templates and Story Mode source pairs, both READMEs, the Sync Loop declaration and the playbook. No routing, confidence, intake, export naming or kernel statement changed.

### Why

After the first remeasure round, rows still dropped or reworded a supplied value. A read-only investigation traced each miss. Task Mode had no rule that a supplied value travels into a task unchanged, since every such rule was written for a Story, so `HMAC-SHA256`, the status word `deprecated` and the service `booking-service` came and went between runs. Doc Templates never said the Behavior reference's primary heading keeps its scaffold name, and never said a backticked rule phrase such as `one discount code per order` is literal copy. Story Mode told the runtime to rewrite source prose and named no exception for an open question, so every run reworded `Do sub-pages inherit the link?`.

### What changed

- Task Mode, on the Core Rules line that already preserves source structure: a value a requirement builds or checks, an event, property or service name and a status word such as `deprecated` or `proposed` travel as the source writes them, inside backticks. A supplied value is a constraint rather than HOW, a status keeps its word beside its meaning, and no generic stand-in replaces a named service. The Content Validation line asks for it
- Doc Templates: a Behavior reference keeps `## Behavior rules` as its primary body heading and puts the subject's wording in the H3s beneath it, and a phrase the source sets in backticks appears word for word in the sentence that states its rule
- Story Mode: an open question the source words itself is carried verbatim, so the `**Open:**` line quotes it and then names who settles it
- The playbook root grades a backticked Pass-clause value word for word where the source sets it in backticks, gives it as a defined label or the clause says verbatim, and accepts the same value in other words elsewhere. The long integration task no longer demands the carrier's retry count and schedule word for word and accepts the board in the reply, the Android subtask lists `99` as it lists `365`, and the proposal accepts the current mechanism restated

### Versions

The Task Mode pair moves to v0.306, Doc Templates to v0.108 and Story Mode to v0.404, each Project mirror renamed with every live reference repointed. Every source edit stayed on its own line, so no line the playbook cites moved. The playbook root moves to 2.2.0.0, the three edited scenario pairs to 1.1.0.0 and the Project scenarios whose links were repointed by a patch step. `SKILL.md` moves from 1.12.0 to 1.13.0 and `description.json` from 1.12.0.0 to 1.13.0.0. The kernel stays at v1.16.0, and its review by the operator is pending.
