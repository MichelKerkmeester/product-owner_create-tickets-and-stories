# v1.7.0.0, Stories and Epics Replace Size Tiers

PRD Mode now writes two artifact kinds, a Story and an Epic. This release replaces the size tiers with story and epic shapes. The Simple, Medium and Complex tiers are gone.

A Story keeps requirements as bold-lead outcome bullets. It never uses a build checklist. An Epic has a goal, a scope of child stories and acceptance criteria at release level. It has no requirements section. Both shapes close with a Delivery section that holds Estimation, Rabbit holes and No-gos.

## Why This Release

The Barter team writes a Story and an Epic in ClickUp. PRD Mode sorted work into Simple, Medium and Complex tiers. The skill carried an Epic reference and had no template for it.

The four dated Onboarding v2 stories and the Onboarding v2 epic are the structural basis. They live under Product Context. They govern structure only. This release does not modify them.

Story and Epic are artifact kinds. They are not size tiers.

## What's New at a Glance

- **Story and Epic replace the size tiers.** Simple, Medium and Complex are retired. PRD Mode writes Story and Epic as artifact kinds.
- **A Story states outcomes.** **Breaking:** The requirement Checklist is removed. Requirements are bold-lead names with natural asterisk outcome bullets and optional supplied screenshots.
- **The Story title is a plain hyphen path.** It is `{Persona} - {Area} - {Feature}`. It drops the `PRD -` prefix and the BO, BE and FE short codes.
- **An Epic is a real supported shape.** It has a Goal, a Scope of child stories and release-level acceptance criteria. It has no Requirements section.
- **Delivery closes every artifact.** The closing section holds Estimation, Rabbit holes and No-gos.
- **Commands select the shape.** `$prd` and `$p` select a Story, with `$story` and `$s` as aliases. `$epic` and `$e` select an Epic and both families resolve to PRD Mode.
- **Wording can select an Epic.** A request to write, create or refine an epic selects the Epic shape, as does an `# Epic -` H1. A brief with no requirements is now a valid Epic signal.
- **Lookalike tokens do not select an Epic.** `$epics`, `$email` and `$e.md` are excluded by the standing exact-token boundary rule.
- **Optional enrichments remain.** Connextra user-story blocks, per-requirement value lines, Rule blocks, Which-means-that and Definition of Ready/Done stay available.
- **The examples follow the new shapes.** The four PRD examples are rewritten as Stories on fictional products. The new example `prd-example-epic` shows an Epic and the README lists 20 examples.
- **PRD intake retires tier inference.** It resolves Story or Epic as the artifact kind. The alias map includes `$epic` and `$e`.
- **The kernel review remains.** The remaining gate is the mandatory kernel review for the contract-input change, per `SYNC.md` section 5.

## The Story Shape

#### Requirements State Outcomes

**Breaking:** The requirement Checklist is removed.

A requirement is now a bold-lead name followed by natural asterisk outcome bullets. It may include optional supplied screenshots. It never includes a Checklist. A Story is an artifact kind.

The Simple, Medium and Complex tiers are retired.

&nbsp;

#### The Title Is a Plain Path

The Story H1 drops the `PRD -` prefix and the BO, BE and FE short codes. The title is the plain hyphen path `{Persona} - {Area} - {Feature}`.

The preamble used to be a blockquote. It is now plain italic lines. Under About, Expected outcomes and References sit at H4.

---

## The Epic Shape

#### An Epic Is a Supported Shape

The skill carried an Epic reference and had no template for it. The Epic is now a real supported shape. Its H1 is `Epic - {Persona} - {Area}`.

It carries a Goal heading at H3 and a Scope heading at H2. Scope lists the child stories and may include an Added Later group. It keeps acceptance criteria at release level. The Epic has no Requirements section.

---

## The Delivery Close

#### Delivery Closes Every Artifact

Every Story and every Epic closes with a Delivery section. The section holds Estimation, Rabbit holes and No-gos.

---

## Command Routing

#### Exact Commands Select the Shape

`$prd` and `$p` are the primary commands for the Story shape. `$story` and `$s` are aliases. `$epic` and `$e` select the Epic shape. All of these are exact PRD Mode commands.

The two families never conflict. Both resolve to PRD Mode. Embedded tokens are excluded by the standing exact-token boundary rule. The excluded tokens are `$epics`, `$email` and `$e.md`.

The skill and Custom Instructions carry the same routing. Export naming includes the Epic. Residual tier language is removed from the skill. The command registry and the export-naming examples include the Epic.

&nbsp;

#### Wording Selects an Epic

A request to write, create or refine an epic selects the Epic shape. An H1 of `# Epic -` also selects it.

A brief with no requirements used to raise a clarification. The clarification called the work "an epic brief, not a PRD". That case is now a valid Epic-shape signal.

&nbsp;

#### Intake Resolves the Artifact Kind

PRD intake retires tier inference. It resolves the artifact kind as a Story or an Epic. The alias map includes `$epic` and `$e`.

## Worked Examples

#### Examples Follow the New Shapes

The four PRD examples are rewritten to the Story shape on fictional products. A new Epic example, `prd-example-epic`, shows the Epic shape. The README updates its PRD Mode section. The example count is 20.

## Upgrade Notes

- **Adopt.** Write a Story with the H1 `{Persona} - {Area} - {Feature}` and outcome bullets. On a Story, put Expected outcomes and References at H4 under About. Write the preamble as plain italic lines. Write an Epic with the H1 `Epic - {Persona} - {Area}`, a Goal, a Scope of child stories and release-level acceptance criteria. An Epic has no Requirements section. Select a Story with `$prd`, `$p`, `$story` or `$s` and an Epic with `$epic` or `$e`. Close both with a Delivery section of Estimation, Rabbit holes and No-gos. Treat a brief with no requirements as an Epic.
- **Drop.** The Simple, Medium and Complex tier model, the requirement Checklist, the `PRD -` title prefix and the BO, BE and FE short codes.
