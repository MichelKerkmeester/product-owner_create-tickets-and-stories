## [**1.6.0.2**] - 2026-08-10

PRD opening restructure. The first part of a PRD / Story artifact now follows the team's real house opening, derived from the `FS - Creator - Onboarding v2` ClickUp epic: an `## About` narrative umbrella (scope, value and user-story promise in prose, with an optional state/lifecycle map), then `### Problem`, `### Solution`, `### References` (Components, Visuals, Flows, governing spec) and `### Expected Outcomes`. Problem and Solution sub-blocks move out of the About block to H3 group sections, matching the Fv2.5 heading scheme.

> Scope: `prd-templates.md` house shape and shared rules, `prd-mode.md` create workflow and quality checklist, the four PRD examples' openings, and the kernel's PRD formatting contract (which also corrected a pre-existing H2/H3 drift where the kernel anchored PRD major sections at H3 while the authoritative sources anchor them at H2). No routing, tier, confidence or gate behavior changed, so `SKILL.md`, `AGENTS.md`, the router and the fixture set are untouched. All mirror version pins reused; the six PRD mirrors re-derived byte-identical.

### Optional / redundant section review

The restructure also encoded which current template sections are optional or redundant:

- **`#### **User Story**` block → optional.** The About narrative now carries the promise. The Connextra block survives as optional enrichment 4.1, placed under `### Solution`, for Complex epics that need explicit promise lines; per-requirement `**PRD:**` value lines already cover requirement-level promises.
- **`#### **Documentation**` link enrichment → folded into `### References`.** References is now the single home for link groups (Components, Visuals, Flows, governing spec); the standalone enrichment is removed.
- **`### Problem` → optional at Simple.** A copy-tweak PRD may have no current state to break; drop it when there is genuinely nothing to describe.
- **`### References` → required only when links exist.**
- **`### Expected Outcomes` → required; explicitly split from Acceptance criteria** (outcomes describe the epic-level why; criteria verify the requirement-level what).
- **`### Coming up` → considered and dropped.** The source epic has it, but the owner removed it from the template and examples before release; the house format teaches About through Expected Outcomes only. Teams can still append the section to a real epic when they need it; the template does not.
- Blockquote preamble, Mention line, DoR/DoD, Rule blocks, Which-means-that, value lines and the shared-mechanism section keep their existing status.
