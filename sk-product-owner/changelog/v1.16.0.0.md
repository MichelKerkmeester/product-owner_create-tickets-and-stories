## [**1.16.0.0**] - 2026-09-26

The templates now match how the operator writes in ClickUp. Story and Epic openings sit at H4, Expected outcomes is a bold label inside Solution, About is H2 in every template, Story requirements are checklist items, and every checkbox is written `[]` with no space.

> Scope: the five templates, the Story, Task, Bug, Doc and Interactive Mode references, Quality Scoring, `SKILL.md`, `AGENTS.md`, the kernel, every mirror, 17 examples, the playbook, both format validators and the 78 benchmark exports.

### Why

The operator's newest hand-written exports already used these forms, and the templates still taught the old ones. The rules also banned a checkbox inside a Story's Requirements, and the format gate blocked one, so a Story written the operator's way failed the gate.

### What changed

- A Story opens with `## About`, then `#### Problem` and `#### Solution`. Solution closes on a bold `**Expected outcomes**` label with a `* * *` divider under it, never a heading
- An Epic's Problem, Goal and Solution sit at H4 too, and the spacers between them are `####   `
- Task and Bug templates write `## About` at H2 and keep their other sections at H3
- A Story requirement is a `- []` item under its bold group name. Items stay hard constraints, never build steps, and a `**Checklist**` label is still banned
- Every checkbox in an artifact is written `[]`: Mark-as-done lines, Ready and Done gates, Task and Bug checklists, and `*   []` in a Doc. The model's own quality checklists inside the references keep `- [ ]`, since they are never output
- "Build checklist" now reads "build steps" wherever it meant implementation steps in Requirements, so the new checkbox marker is not read as banned

### Gate

Both format validators, the shared one and this system's own copy, read `[]` and `[ ]` as checkboxes, so every rule that used to miss `[]` still fires. Under `## Requirements` a plain `*   ` bullet now blocks and a checkbox item passes. A new rule blocks a `[ ]` checkbox in a Product Owner deliverable, keyed per system so other systems and the sources are untouched. On the old exports it finds all 815 spaced checkboxes and all 290 plain requirement bullets.

### Known risk

Standard markdown renders only `- [ ]` as a checkbox, and every ClickUp note in this repo was checked with that form. How ClickUp renders `- []` is unverified. The operator chose `[]` knowing this.
