## Doc and Story Debut

#### Two New Routed Intents

Doc and Story joined Task, Bug and Interactive as routed intents for the first time. Neither existed anywhere under the old `skill/` tree. No doc or story file appears at any earlier point in this repository's history, so this routing has no prior baseline.

The new files are `references/doc-mode.md`, `assets/doc-templates.md`, `references/story-mode.md` and `assets/story-templates.md`. All four entered git already past v0.100. The versions recorded at entry are v0.105, v0.106 and v0.102, evidence of drafting cycles that ran before this repository ever tracked the files.

&nbsp;

#### Examples and Carried Templates

Seventeen worked examples shipped under `assets/examples/`. Four are Bug, six are Doc, three are Story and four are Task. `bug-report-template.md` and `task-templates.md` carried over from the old `skill/` assets with light edits.

## The Skill Package

#### Folder Rename and Skill File

The skill folder renamed from `skill/` to `sk-product-owner/`. `SKILL.md` moved from version 1.1.0 to 1.4.0, gained a keywords HTML comment and kept its seven numbered sections, WHEN TO USE through INTEGRATION POINTS.

Five separate dictionary blocks in Python code fences collapsed to one. Four of the five old blocks were static `INTENT_MODEL`-style dictionaries that nothing in a markdown file ever executed, and they folded into one working Smart Router Pseudocode block. That block carries real imports, a token-boundary regex and named confidence thresholds.

&nbsp;

#### Advisor Metadata and the README

`description.json` and `graph-metadata.json` arrived for the first time. They give the skill a version-pinned manifest at 1.4.0.0, a 31-entry keyword list and ten trigger examples. Graph edges name `mcp-tooling` as an enhanced skill and `sk-doc` as a sibling.

The package-root `README.md` was a stale v0.096 guide still describing Task v0.223 and Bug v0.127 templates, several versions behind anything in the current tree. It is now a single line, a relative symlink to `sk-product-owner/README.md`.

## Boundaries and Handoff

#### Source-Backed Technical Writing

`AGENTS.md` rewrote its Boundaries section. The old text was a hard refusal, "you are NOT a developer, you do NOT write code". The new boundary is documentation-aware. It allows source-backed technical HOW, architecture, APIs and explicitly labelled proposals. It still forbids fabricated implementation facts and false approval.

&nbsp;

#### Read-Back and ClickUp

The Strict Sequence gained a mandatory read-back step. Export verification now requires Read to return non-empty content at the saved path before the response claims delivery. That replaces the earlier one-line instruction, "verify the file saved successfully."

A new ClickUp Handoff section lets both runtimes offer ClickUp delivery after export. It forbids writing to ClickUp without explicit per-conversation approval.

`SYNC.md` was rewritten from an unnumbered four-section note into an eight-section document, OVERVIEW through RELATED DOCUMENTS, on the sk-doc section standard. It has frontmatter, a manual-load contract, a thirteen-row source-to-mirror inventory and a nine-point drift-check list. It states that the Project Knowledge package now contains exactly thirty files, thirteen core mirrors and seventeen worked examples.

The `knowledge/` folder holds exactly 30 files, matching the inventory `SYNC.md` declares.

## Custom Instructions Drift

#### Export Paths Add Doc and Story

A drift pass in the same commit fixed four gaps in `Custom Instructions.md`. The export-path examples had been one stale line naming only task, subtask, parent-task, bug and acceptance-criteria. They are now seven per-intent lines that add doc and story.

&nbsp;

#### Shapes and Heading Depth

The shape list gained its fifth entry, Narrative overview, alongside Guide, Catalog, Behavior reference and Proposal. A heading-depth rule states that H1 is the title only and that H2 stays a minority of the document's headings. That rule closes the heading-ladder gap.

&nbsp;

#### A Five-Part Doc Verdict

The Doc deliverable's quality status is now a dimensioned verdict. It is one pass-or-attention line each for Source safety, Shape fit, ClickUp layout, Readability and Voice.

## Mode Hardening

#### Versions After the Morning Pass

A follow-up the next morning bumped `doc-mode.md` to v0.106, `doc-templates.md` to v0.107, `task-mode.md` to v0.303, `bug-mode.md` to v0.202 and `story-mode.md` to v0.103. `description.json` `lastUpdated` still reads `2026-07-16T00:00:00Z`. This pass did not change it.

&nbsp;

#### Doc Shape and Tables

`doc-mode.md` gained a five-line decision tree for shape selection, placed ahead of the existing shape-by-shape prose. The tree runs from "does the reader follow an order or apply a standard" through "does the reader need orientation and story".

`doc-templates.md` added a Table Patterns subsection. It names three legitimate table uses, Index, "Options and trade-offs" and "Conditions and outcome". It also adds five Section | Include when tables, one per Doc shape, so an optional section earns its place only when its stated condition holds.

&nbsp;

#### One Quality Check per Mode

Each of Doc, Bug, Task and Story gained one quality-checklist line. Doc checks every included section against its Include when condition. Bug pairs the decisive reproduction step with its expected and actual result when the evidence supplies both. Task checks that supplied links resolve or get flagged in prose. Story adds a reader-simulation check that a developer could cut a ticket from each requirement without a follow-up question.
