# v1.2.0.0, Stories and Epics by Name

The system ships two artifact kinds, Story and Epic, but much of its text still called them PRDs, and the per-requirement value line printed `**PRD:**` into every Story that used it.

## What's New at a Glance

- **The value line reads `**Story:**`.** The optional Connextra line under a requirement now opens `**Story:** As a ...`, in the Story Mode template and the maximal worked example.
- **The rules name the artifact.** The skill, the kernel, the mode references, the quality checks, the intake questions and both READMEs say Story or Epic wherever they meant the artifact. The kernel section is now "ClickUp And Story Formatting Contract".
- **The examples carry the story name.** `assets/examples/story/prd-example-*.md` became `story-example-*.md`, matching the `doc-example-` and `task-example-` files beside them. The manifests, the README, Story Mode and the Sync Loop declaration point at the new names.
- **The router topic is `story`.** The semantic topic that routes to Story was keyed `prd`. It is now `story` in the router contract, the kernel's copy and the benchmark's executable copy, with the same synonyms, weight and override.
- **What stays.** `$prd` and `$p` remain back-compat aliases for `$story`. Users who type "PRD" in a request still route to Story, and "create a task to write a PRD" still stays Task. The ban on an old `PRD -` title prefix is unchanged.
- **Smaller fixes found on review.** The Router Contract's example sentence now counts twenty-one documents with no version suffix, as the kernel already did. Story Mode's Project copy names each example by its Knowledge title, as Task Mode does. Quality Scoring and Interactive Mode gain the `---` separators their numbered sections were missing, on both sides.
- **The kernel moves to v1.2.0.**
