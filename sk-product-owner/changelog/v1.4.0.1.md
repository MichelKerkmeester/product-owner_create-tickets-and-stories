# v1.4.0.1, Kernel Aligns with the Claimed Skill

The 1.4.0.0 release had synthesized `Custom Instructions.md` against Skill 1.4.0, but the kernel had drifted from its own source mirror in eight places. This release corrects the kernel, the README and the shared references so the package is back in alignment with the Skill it already claimed to match. `SKILL.md` itself stays pinned at 1.4.0.

## What's New at a Glance

- **The Deliverable Block protocol overrides mirror save instructions.** `Custom Instructions.md`'s Export-Equivalent Paths section named the runtime `Path:`/`Saved:`/`Verified:` restriction but never said it overrides the retrieved System Skill mirror's filesystem save-and-read-back instructions. The section now states that this protocol overrides those mirror instructions, so the contradiction resolves inside the kernel.
- **Raw energy and skip depth are in the kernel.** A `DEPTH Raw` line joined the Processing list, which named only Standard, Quick, Deep and Interactive. A Routing and Energy rule states that `skip depth` is the explicit trigger for Raw energy and that `$quick` never selects it, matching `SKILL.md`'s energy-level definition.
- **The four confidence bands are explicit.** The kernel routed by confidence without ever naming a threshold. A Routing and Energy line now states HIGH `>= 0.85` direct, MEDIUM `>= 0.60` confirmed, LOW `>= 0.40` suggested through Interactive Mode and FALLBACK `< 0.40` one comprehensive question, verbatim from `SKILL.md`.
- **Perspective counts now block delivery.** The Quality Gate now states that Standard must clear 3 of 5 canonical perspectives and Deep must clear all 5, as floors that block delivery exactly like the dimension floors. The closing Quality Checklist gained Story alongside Task, Bug and Doc, matching `SKILL.md`'s five-intent list.
- **ClickUp consent now covers any external system.** Two consent lines and the ClickUp Connector Delivery section now match `SKILL.md`'s NEVER rule, which already generalizes consent to "ClickUp or another external system." The Connector Delivery section also gained the task read-back step, `include_markdown_description=true` confirmed against the pushed body before delivery is reported complete, matching `SKILL.md`'s ClickUp Transport table.
- **Pins and the mirror count match the live files.** The Smoke Matrix in `claude project/README.md` cited Task `v0.302` and Bug `v0.201` and now cites live Task `v0.303` and post-bump Bug `v0.203`. `Custom Instructions.md` had described thirteen uploaded Project Knowledge mirrors against a live count of thirty and now states the thirteen core mirrors plus seventeen examples the `knowledge/` folder still holds.
- **Cross-references now resolve in the skill tree and the flat mirror.** `bug-mode.md` replaces a nonexistent "Owner - Templates - Task Mode" and a directory-relative Bug Report Template path, which resolved only inside the skill tree, with `Templates - Task Mode` and `Assets - Bug Report Template`. `depth-framework.md` now uses `Human Voice Rules` in the two places that named "Owner - Rules - Human Voice.md", `depth-framework.md` moved from `v0.201` to `v0.202`, `bug-mode.md` moved from `v0.202` to `v0.203` and the superseded mirror filenames were removed.
- **Seven new Smoke Matrix cases close Drift Checks 6 through 9.** They cover Task, Bug and Story resource loading, `skip depth`, Quick/Story order, task read-back, the ClickUp `content_format` parameter and file-export spacer-heading exclusion. `SYNC.md` Drift Checks 6 and 8 now name `skip depth` routing, task read-back and `content_format` explicitly.
- **Custom Instructions moved from v1.2.0 to v1.3.0.** `Custom Instructions.md` moved from `v1.2.0` to `v1.3.0` for the kernel-semantics changes above.
