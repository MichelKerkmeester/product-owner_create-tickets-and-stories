# v1.11.0.0, Ask First and Keep Claims Honest

Six operator decisions come from grading the 2026-09-25 Opus 5.5 medium playbook run. An explicit command always asks first. An Epic writes References only when a link is supplied. A promise to write a file counts as a file claim in a Project. A bug never asserts that no error message appears when none was supplied.

In the playbook the Behavior reference scenarios draft at once from their attachments. The two-platform log bug allows a cause labelled as an unverified hypothesis. Four are rule changes, so the skill moves to 1.11.0 and the Project kernel to v1.15.0.

## Why This Release

`AGENTS.md` and the kernel said `$task`, `$bug`, `$doc` and `$story` still ask their mode's question, and `references/task-mode.md` carried the same exception. Bug Mode, Story Mode and Doc Mode each let a request with enough context draft at once and named no exception for a command. The Interactive Mode state machine sent `$doc`, `$story` and `$epic` straight to a gate that drafts whenever nothing is missing.

The Epic scaffold and every Epic statement listed `#### **References**` with no way out, although none of the Epic scenarios supplies a link, so a correct Epic had to carry an empty block or an invented one. The Project kernel forbade claiming a save and said nothing about promising one.

The bug template's Observed Behavior slot read "Any error messages displayed", and all three skill bugs in the run wrote "No error message is shown" when no ticket, log or turn said so. `SDK-001` and `PDK-001` expected a Turn 1 question from a request with no command whose attachments answer every field Doc Mode asks about. `SBG-003` and `PBG-003` passed only with "no root cause for either issue", which read stricter than the root's Defect severity, where a cause the artifact labels as an unverified hypothesis is not an invented one.

## What's New at a Glance

- **An explicit command asks before it drafts.** `$task`, `$bug`, `$doc`, `$story` and `$epic`, their short aliases and the `$prd` and `$p` aliases ask their mode's question and wait, however much context the request carries. Only `$quick` or `$q` may skip routine intake.
- **A request with no command can draft when the context is enough.** In Bug Mode, Story Mode and Doc Mode that branch now applies to requests with no command. `SKILL.md` states it in the Clarification Protocol.
- **Interactive Mode asks before the draft gate.** Doc, Story and Epic commands go to their clarification question before the gate. The Story Context Question is used for every explicit Story or Epic command.
- **An Epic lists References only for a supplied link.** The block carries supplied links only and is left out when none are supplied, never empty and never invented. The kernel now says this for both shapes, so the Story reads no stricter there than its own scaffold.
- **A promise to write a file counts as a file claim.** The kernel's NEVER 3 forbids a promise to write or save a file as well as a claim that one was saved. An export-equivalent path is a label and not a file the Project writes.
- **A bug records an error only when one was supplied.** Observed Behavior asks for an error message the ticket, log or user supplied. With none supplied the line reads `Not provided` or is left out, and it never states that no error message appears.
- **The playbook counts a file promise as a Project claim.** The playbook root counts a promise to write or save a file as a Project-side file claim in the Identity handover rule and in Defect severity. A follow-up change to a delivered doc may update that export in place or take the next number.
- **Behavior reference scenarios draft on Turn 1.** `SDK-001` and `PDK-001` keep their Turn 1 input and attachments word for word. Turn 1 now drafts the Behavior reference at once in the doc lane and Turn 2 is a follow-up carrying the direction the old Turn 2 supplied.
- **Epic scenarios require References only for a supplied link.** The six Epic scenarios require References only when a link is supplied, never empty and never invented.
- **Log scenarios allow an unverified hypothesis.** `SBG-003` and `PBG-003` fail a cause stated as fact or one cause given to both issues. They allow a cause the artifact labels as an unverified hypothesis, as the root's Defect severity already does.
- **Package versions move forward.** Bug Mode moves to v0.204, Story Mode to v0.403, Doc Mode to v0.111, Interactive Mode to v0.406, Interactive Response Templates to v0.103, the Epic Template to v0.101 and the Bug Report Template to v0.101. `SKILL.md` moves from 1.10.0 to 1.11.0, `description.json` from 1.10.0.0 to 1.11.0.0, the kernel from v1.14.0 to v1.15.0 and the playbook root to 2.1.0.0.

## Command Intake

#### Commands Ask Before They Draft

Bug Mode, Story Mode and Doc Mode each let a request with enough context draft at once and named no exception for a command. An explicit command now routes the request and does not supply the direction. `$task`, `$bug`, `$doc`, `$story` and `$epic`, their short aliases and the `$prd` and `$p` aliases ask their mode's question and wait, however much context the request carries. Only `$quick` or `$q` may skip routine intake.

&nbsp;

#### Enough Context Applies With No Command

The branch that drafts when the context is enough now applies to requests with no command. `SKILL.md` states it in the Clarification Protocol. An explicit command routes the request and does not supply the direction.

&nbsp;

#### Interactive Mode Asks Before the Gate

The Interactive Mode state machine sent `$doc`, `$story` and `$epic` straight to a gate that drafts whenever nothing is missing. Interactive Mode now routes the Doc, Story and Epic commands to their clarification question before the gate. The Story Context Question is used for every explicit Story or Epic command.

## Epic References

#### Supplied Links Are the Only References

The Epic scaffold and every Epic statement listed `#### **References**` with no way out, although none of the Epic scenarios supplies a link, so a correct Epic had to carry an empty block or an invented one.

An Epic's `#### **References**` now carries supplied links only and is left out when none are supplied, never written empty or with an invented link. That is the rule the Story scaffold already stated. The kernel now says this for both shapes, so the Story reads no stricter there than its own scaffold.

---

## File Claims

#### A Promise Is a File Claim

The Project kernel forbade claiming a save and said nothing about promising one. NEVER 3 now forbids a promise to write or save a file as well as a claim that one was saved, because an export-equivalent path is a label and not a file the Project writes.

&nbsp;

#### The Playbook Scores That Promise

The playbook root counts a promise to write or save a file as a Project-side file claim in the Identity handover rule and in Defect severity. It also allows a follow-up change to a delivered doc to update that export in place or take the next number.

## Bug Reports

#### Record Only a Supplied Error

The Observed Behavior slot read "Any error messages displayed", and all three skill bugs in the run wrote "No error message is shown" when no ticket, log or turn said so. The slot now asks for an error message the ticket, log or user supplied. With none supplied the line reads `Not provided` or is left out, and it never states that no error message appears. Bug Mode's Observed Behavior rule and its checklist item say the same on both sides.

## Playbook Scenarios

Both twins of every pair keep identical turns.
