# v1.2.3.0, A Board Command Conflict Asks About the Artifact First

The graded Claude Sonnet 5.5 high FigJam run found that Interactive Mode's one comprehensive question pulled board questions into the reply that settles a command conflict. `references/interactive-mode.md` now keeps the two apart. No template, example or other route changed.

## What's New at a Glance

- **The artifact comes first.** When two artifact commands conflict and one of them draws a board, such as `$task $flow`, the first question settles the artifact and asks no board fact. The board facts wait for Flow Mode's own round
- **Quick marks every inferred row.** A Quick board request marks each Brief row it inferred `assumed` with what would settle it, however many rows that is, so a thin brief still reaches the offer to draw

## Upgrade

In the claude.ai Project, replace System - Interactive Mode. The kernel needs no change of its own for this release, so kernel v1.2.7 from `sk-create-figjam` v1.0.6.0 covers it.
