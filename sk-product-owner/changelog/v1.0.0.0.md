# v1.0.0.0, SKILL.md Under the Word Cap

The sk-doc package check caps `SKILL.md` at 5,000 words, and Product Owner's ran to 7,814. Most of the excess restated what a mode reference loaded on the same route already says, so `SKILL.md` now points there instead of repeating it.

## Version Numbering

This is the first stable release. Every earlier release is renumbered as a pre-release: v1.a.b.c became v0.(a+1).b.c, so the previous release, once v1.16.3.0, is now v0.17.3.0. The Project kernel moves to v1.0.0 the same way, and its earlier versions move from v1.a.b to v0.(a+1).b.

## What's New at a Glance

- **Section 3 points at the mode references.** The Doc fidelity, authority and ClickUp layout detail lives in `references/doc-mode.md`, the house grammar in `references/story-mode.md`, the Story bundle layout in the Story With Nested Tasks section of `references/story-mode.md`, and the list of what a deliverable never contains in `references/conciseness.md` Section 8. `SKILL.md` keeps the rule and names where its detail sits.
- **Section 6 keeps the floors and the gates.** The floor table drops its Measures column, which `references/quality-scoring.md` Section 2 carries, and the Story and Doc gates name the reference they are checked against.
- **The ClickUp transport table moves into Section 7**, beside the approval rule it serves, so it is stated once.
- **Rule numbering is unchanged.** Every ALWAYS and NEVER rule keeps its number, and the statements the playbook cites keep their wording.
- **A shorter description.** The frontmatter description is 119 characters, under the 130-character target.
- **Worked examples carry `importance_tier` and `trigger_phrases`**, as every other resource does.
- **The kernel stays at v0.22.0** and no Knowledge file changed, because `SKILL.md` is not mirrored and every moved statement already sat in a mirrored reference.
