## [**1.6.0.0**] - 2026-08-06

Superseded counts: the route object gained `shape` and `on_demand`, so it carries eight fields rather than the six described below, and the fixture manifest has grown past a hundred entries. The paragraphs below are the record of this release and are left as written. `benchmark/router/README.md` carries the current shape.

Smart-routing parity release. Product Owner joins the fleet-wide routing hardening: Section 2 now carries the canonical five subsections in a fixed order, an executable route contract characterizes routing without invoking a model, and `Custom Instructions.md` becomes the sole routing authority in the claude.ai Project because the SKILL mirror no longer ships there.

> Scope: two new SKILL.md subsections (Primary Detection Signal, Resource Domains) plus a rename (Detection Sequence to Phase Detection) and an oracle-binding sentence, a new `benchmark/router/` package (23 fixtures, all passing), a full Custom Instructions rebuild carrying the same five routing subsections plus an ALWAYS/NEVER/ESCALATE rules section, and the SKILL mirror's removal from Project Knowledge. No artifact intent, command token, framing rule, confidence threshold or Doc/Story delivery contract changed.

### SKILL.md Section 2 Carries The Canonical Five Subsections

`SKILL.md` (v1.5.0 to v1.6.0) restructured Section 2 so it carries, in order, Primary Detection Signal, Phase Detection, Resource Domains, Resource Loading Levels and Smart Router Pseudocode. Primary Detection Signal is new: an ASCII arrow map of every command, framing and confidence-fallback route. Resource Domains is new: it names where `references/` and `assets/` resources come from, including the shared `human-voice-rules.md` symlink. `Detection Sequence` renamed to `Phase Detection` with its nine steps unchanged. The existing Confidence Thresholds subsection and Smart Router Pseudocode's already-exact `has_exact_token`/word-boundary `score_semantic_topics` logic did not need behavior changes; they already matched the canonical exact-token, word-boundary contract. A new sentence directly under the `## 2. SMART ROUTING` header states that the executable oracle in `benchmark/router/` must never drift from this prose.

&nbsp;

### Executable Route Oracle Added

`benchmark/router/` is new: `route_contract.py`, `fixtures.json` (23 fixtures), `run_fixtures.sh` and `README.md`. The contract returns a fixed six-field route object (`intent`, `energy`, `source`, `confidence`, `needs_disambiguation`, `resources`) built from exact `$token` detection, word-boundary keyword scoring with the same 0.85 documentation/story confidence override as the skill, artifact-framing patterns, and confidence-gated directness (Standard routes at 0.60+, Quick at 0.40+ and otherwise falls back to Task). `validate_route_object` rejects unknown, missing or duplicate fields and invalid enum values. Resource resolution discovers the live `references/*.md` and `assets/*.md` inventory at every call and guards every load through a lexical `.absolute()` fence, so a renamed or deleted reference degrades instead of crashing, and the shared Human Voice Rules symlink resolves correctly. The fixture set covers every dollar-command including `$task --subtask`, natural-language framing per artifact, a command-precedence case (`$doc` beating a `bug report` framing collision), a two-command conflict, the Quick-energy 0.40-vs-Standard 0.60 threshold divergence, and two adversarial cases: a word-boundary keyword (`bug` must not match inside `debugging`) and an exact-token command (`$doc` must not match inside `$document`). `run_fixtures.sh` prints `PASSED 23/23 fixtures` and exits 0; both adversarial inputs were also run directly and route to Interactive Mode as required.

### Custom Instructions Rebuilt As The Sole Routing Authority

`Custom Instructions.md` (v1.4.0 to v1.5.0, aligned to Skill v1.6.0) was rebuilt end to end. Section 2 now carries the same five routing subsections as the skill, advisory-adapted: the Smart Router Pseudocode subsection restates the executable oracle's decision order as numbered prose instead of code, since a Project cannot execute it. A new Section 3 Rules carries the skill's full ALWAYS (15 items), NEVER (15 items, including an advisory-truthfulness item barring any claim of local execution) and ESCALATE IF rules, advisory-adapted for a Project that cannot write files or call ClickUp without the connector. The prior Critical Rules numbered list, Refusal and Clarification section and standalone Escalation section were consolidated into this structure with no rule dropped: routing tie-breaks moved into Phase Detection, source-authority ordering and Doc Shapes detail moved into a rebuilt Doc Shapes and Source Contract section (now with an explicit ClickUp And Story Formatting Contract subsection), and every remaining item landed in ALWAYS, NEVER or ESCALATE IF. Operating Model, Doc Shapes, Quality Gate, Smart Routing Matrix, Project Knowledge Consultation, Delivery Protocol and Quality Checklist all carried forward with their existing domain content intact, renumbered to fit the new section order.
