# v1.2.21.0, Design Copy Stays in the Design

A Story fed many screenshots used to transcribe their copy, one backticked string per button, heading and toast. The rules now split copy by where it came from.

## What's New at a Glance

- **Typed copy travels verbatim.** A string the requester types is copied into its constraint item inside backticks, as before
- **Screen copy stays in the design.** A screenshot supplies its values, states and element order, never its copy or labels
- **The change is quoted once.** A string the requester says is itself the change is the one string a screenshot supplies
- **Elements by role.** A rule and a Given, When or Then line name the primary action, the empty-state label or the confirmation toast, never the label a design gives it

## Changed

- Story Mode, the Story template and the sectioned Story example state the split rule, and the example names its empty states by role
- The narration check's repair now strikes the item instead of quoting the copy into it
- The format gate advises on a Story or Epic whose Requirements and Acceptance criteria quote twelve or more distinct copy-like strings. It never blocks, because it cannot tell typed copy from copy read off a design
