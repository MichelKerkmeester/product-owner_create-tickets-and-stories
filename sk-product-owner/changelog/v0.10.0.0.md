# v0.10.0.0, Disclosed Additions and Saved Clarifications

A disclosed addition is no longer an invented requirement, and a clarification is saved and read back like any artifact. The kernel's NEVER list carries the invention ban and the disclosure rule as item 6, so a Task run holds them without opening Doc Mode knowledge. A session with no Canvas panel puts the Deliverable Block first.

## Why This Release

From the Claude Sonnet 5 medium playbook run of 2026-09-25, seven scenarios per packaging, on four operator decisions. `SKILL.md` asked for edge cases and assumptions in ALWAYS 8 and banned invented requirements in NEVER 4 with nothing between the two, and on the Project side the kernel sent the invention ban to Doc Mode knowledge alone, which a Task run never opens. `SDK-002` made no tool call on turn 1 and exported no clarification, and the always-loaded `AGENTS.md` never said a clarification is saved. The Project runs had no Canvas panel, a case the kernel's render-first rule did not cover.

## What's New at a Glance

On the operator's decisions:

- **A disclosed addition is allowed.** An edge case, assumption or other addition the user did not supply is allowed only when the chat response names it as an addition, so the user can strike it. An addition the response does not name is an invented requirement, and naming never makes invented evidence, a root cause or a platform detail acceptable.
- **The disclosure rule is recorded in the skill, both mode pairs and the playbook.** It sits in `SKILL.md` NEVER 4 with a pointer from ALWAYS 8, in NEVER 4 on both sides of the Doc Mode pair and in the source-of-truth bullet on both sides of the Story Mode pair. The playbook root names it as the one exception to the invented-fact rule.
- **A Task run holds the ban without Doc Mode.** The kernel's NEVER list carries the invention ban and the disclosure rule as item 6, so a Task run holds them without opening Doc Mode knowledge.
- **A clarification is saved like an artifact.** `AGENTS.md` Section 2 says a clarification is saved to `export/`, read back and reported like an artifact, under the `-clarification` name the Interactive Mode reference and the kernel already used, with `intake` in place of the artifact word when no artifact was resolved. The artifact then takes the next number in that lane and the clarification file stays untouched.
- **A session with no Canvas panel leads with the deliverable.** The Deliverable Block comes first as one fenced block with no preamble about the missing panel, then the `Export-equivalent path:` line. A session that has the panel always uses it.

Versions:

- **Mode pairs and the playbook take new versions.** The Doc Mode pair moves to v0.110 and the Story Mode pair to v0.401, with their mirrors renamed and every live reference repointed. The playbook root moves to 1.0.0.2, and its kernel line citations and those in the Project Doc guide scenario follow the one-line shift.
- **The skill, the description and the kernel move to the release versions.** Each decision is a rule change, so the skill moves to 0.10.0 and the Project kernel to v0.14.0. `SKILL.md` moves from 0.9.4 to 0.10.0, `description.json` from 0.9.0.0 to 0.10.0.0 and the kernel from v0.13.6 to v0.14.0.
