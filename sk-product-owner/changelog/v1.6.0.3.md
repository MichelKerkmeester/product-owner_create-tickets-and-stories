# v1.6.0.3, Requirement Names Lead in Bold

Requirement names in the PRD house format now render as bold paragraph leads under Requirements, matching the bold-item convention Task requirements already use. Gates and spec sub-blocks keep their H4-bold headings, and a PRD never goes deeper than H4. The templates, the four examples and the formatting contract state that split.

## What's New at a Glance

- **Requirement names render as bold paragraph leads.** Under `## Requirements`, each requirement name now renders as `**{Requirement name}**` instead of `#### **{Requirement name}**`. This matches the bold-item convention Task requirements already use.
- **Gates and spec sub-blocks stay H4-bold.** Rule / spec blocks, the optional User Story promise block, Definition of Ready/Done (DoR/DoD) gates and shared-mechanism sub-blocks keep their H4-bold headings. The shared heading-depth rule states requirement names as bold paragraph leads, states gates and spec sub-blocks as H4-bold headings and states that a PRD never goes deeper than H4.
- **The templates teach the house shape.** `assets/prd-templates.md` now teaches requirement names as bold paragraph leads in the house shape, in the per-requirement value-line example (4.2) and in the priority marker (4.8).
- **The four PRD examples were updated in place.** `prd-example-simple.md` has one requirement, `prd-example-medium.md` has three, `prd-example-complex.md` has four including the `← PRIO` marker and `prd-example-complete.md` has three including `← PRIO`.
- **Acceptance criteria keep their numbered blocks.** They stay numbered `1.` bold-title blocks. Only the requirement-name items changed.
- **The formatting contract states the same split.** Heading-depth validation in `references/prd-mode.md` now reads that requirement names are bold paragraph leads and that gates and spec sub-blocks are H4-bold headings. `SKILL.md` and `Custom Instructions.md` carry the same split in their PRD formatting-contract lines.
- **Routing, tiers and gates keep their behavior.** No routing, tier, confidence, gate or delivery behavior changed. No gate, routing or tier logic changed.

## Upgrade

The remaining gate is the mandatory kernel review for the contract-input change, per `SYNC.md` section 5.
