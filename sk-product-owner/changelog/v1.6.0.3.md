## [**1.6.0.3**] - 2026-08-11

Requirement names in the PRD house format move from H4-bold headings to bold paragraph leads. Under `## Requirements`, each requirement name now renders as `**{Requirement name}**` instead of `#### **{Requirement name}**`, matching the bold-item convention Task requirements already use. Rule / spec blocks, the User Story promise block, Definition of Ready/Done gates and shared-mechanism sub-blocks keep their H4-bold headings.

> Scope: the house-shape requirement-name lines and the heading-depth rule in `prd-templates.md`, the requirement names in the four PRD examples, the heading-depth validation line in `prd-mode.md`, and the PRD formatting-contract lines in `SKILL.md` and `Custom Instructions.md`. No routing, tier, confidence, gate or delivery behavior changed. No spec was written for this change.

### Requirement Names As Bold Paragraph Leads

`assets/prd-templates.md` now teaches requirement names as bold paragraph leads in the house shape, in the per-requirement value-line example (4.2) and in the priority marker (4.8). The shared heading-depth rule states the new split: requirement names as bold paragraph leads; gates and spec sub-blocks (Rule blocks, DoR/DoD, shared-mechanism sub-blocks, the optional User Story promise block) at H4-bold; a PRD never goes deeper than H4. The four PRD examples were updated in place: `prd-example-simple.md` (one requirement), `prd-example-medium.md` (three), `prd-example-complex.md` (four, including the `← PRIO` marker) and `prd-example-complete.md` (three, including `← PRIO`). Acceptance criteria stay numbered `1.` bold-title blocks; only the requirement-name items changed.

### Contract Text Aligned

`references/prd-mode.md` heading-depth validation now reads "requirement names as bold paragraph leads; gates and spec sub-blocks as H4-bold headings". `SKILL.md` and `Custom Instructions.md` carry the same split in their PRD formatting-contract lines. No gate, routing or tier logic changed.
