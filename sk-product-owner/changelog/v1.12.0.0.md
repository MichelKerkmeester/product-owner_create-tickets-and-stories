## [**1.12.0.0**] - 2026-09-26

The Project never forecasts a file for an artifact it has not rendered yet, and a clarification reply says the artifact comes next without naming its path. This is a rule change, so the skill moves to 1.12.0 and the Project kernel to v1.16.0.

> Scope: the Project kernel, the Interactive Mode source pair, the Sync Loop declaration, both READMEs and the playbook root. No routing, confidence, template or export naming changed.

### Why

Kernel v1.15.0 forbade promising to write or save a file and quoted an example of the promise it banned. In the remeasure round the Project runtime still forecast the next artifact's file in 8 rows, some in nearly the quoted words: "Once you answer, the task will be `export/002 - ...`", "I'll write the epic as `export/002 - ...`", "It will save as `export/fernhouse-save-card-draft.md`" and "I'll update the same file". The quoted sentence may have been priming the very reply it banned, and the clarification rule on both sides told the runtime which lane and number the artifact takes next without saying the reply leaves that path out.

### What changed

- The kernel's NEVER 3 drops the quoted example and states the rule directly: never say this Project saved, verified, read back, pushed, will write, will save or will update a file. A reply names only the export-equivalent label of the block it renders, never a path or file for an artifact still to come
- The kernel's Clarification label and the clarification reporting paragraph in both Interactive Mode documents say the reply says the artifact comes next once the user answers, without naming the artifact's path or file. The skill side carries it too, so the pair stays identical on that sentence
- The playbook root's Identity handover rule and Defect severity keep the promise example and add a forecast of the next artifact's path, such as "the task will be `export/002 - ...`", as a Project-side file claim

### Versions

The Interactive Mode pair moves to v0.407, with its mirror renamed and every live reference repointed. The two declared kernel statements holding NEVER 3 and the Clarification label were resynced. Every kernel and playbook root edit stayed on its own line, so no line the playbook cites moved. The playbook root moves to 2.1.1.0. `SKILL.md` moves from 1.11.0 to 1.12.0, `description.json` from 1.11.0.0 to 1.12.0.0 and the kernel from v1.15.0 to v1.16.0.
