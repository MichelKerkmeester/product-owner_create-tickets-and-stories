# v0.7.0.1, Story Mode Becomes the PRD

The Story artifact intent is renamed to PRD (Product Requirements Document) across both packagings and the executable route contract. This rename leaves the Barter house-format artifact, the Simple, Medium and Complex tier intelligence, the router logic, every gate and the confidence threshold as they were. Doc, Task and Bug behavior and the delivery contract are unchanged.

## What's New at a Glance

- **The fourth artifact intent is now PRD.** Product Requirements Document replaces Story across both packagings and the executable route contract. `references/story-mode.md` is now `references/prd-mode.md`, `assets/story-templates.md` is now `assets/prd-templates.md` and the four worked examples moved from `assets/examples/story/` to `assets/examples/prd/` as `prd-example-{simple,medium,complex,complete}.md`.
- **Knowledge mirrors kept their version pins.** They were re-derived as `Product Owner - Templates - PRD Mode - v0.200.md`, `Product Owner - Assets - PRD Templates - v0.200.md` and the four `Product Owner - Examples - PRD - *` files. The six superseded Story mirror names were removed from `claude project/knowledge/` and appended to `retiredNames` in `claude-project.sync.json`, with `expectedKnowledgeCount` still 31.
- **`$prd` and `$p` are the primary PRD commands.** `$story` and `$s` are retained as back-compat aliases so existing muscle memory still routes, and all four tokens resolve to the PRD intent. `$prds` and `$stories` remain false-prefix non-commands.
- **The command write-ups match the rename.** `SKILL.md` updates Command Triggers, Primary Detection Signal, Phase Detection, Mode Selection Notes and Success Criteria. `AGENTS.md` updates the Command Registry and Routing Compatibility, `Custom Instructions.md` updates its routing prose, Operating Model and Smart Routing Matrix and `interactive-mode.md` updates command-detection YAML and state names, including `story_intake_gate` to `prd_intake_gate`.
- **The router pseudocode carries the same intent.** The `SKILL.md` Smart Router Pseudocode block names the PRD intent, the command detection and the preserved user-story synonyms. The same block was re-derived into `Custom Instructions.md` on `sync --write`.
- **The story inside a PRD is unchanged.** The rename covers the mode, its commands, its files and the artifact-type label only. The `#### **User Story**` block, the Connextra "As a {role}, I want {capability}, so that {benefit}" lines, the per-requirement `**Story:**` value-line label, the Given/When/Then acceptance criteria and the verbatim ClickUp preamble stay as they were.
- **Story phrases still open PRD Mode.** "write a user story", "turn this into a story" and "refine this story" still route there. Framing and semantic signals now also take `prd` and `product requirements document`, and the natural-quick alternation takes `prd`.
- **New headings and exports use PRD.** The house-format H1 moved from `Story - {Platform/Area} - {Feature} - {Name}` to `PRD - {Platform/Area} - {Feature} - {Name}`. New exports save to `export/[###] - prd-[description].md`.
- **Packaging files stay on their current pins.** `SKILL.md` and `Custom Instructions.md` stay at `0.7.0`, and `description.json` stays at `0.7.0.0`. No mode or template reference version changed.
- **Doc Mode keeps its narrative use of story.** Uses of "story" and "storytelling" in its narrative register were left intact, as were references to the team file `Story - Fv2.5 - Deal Types & Geo Targeting`.

## Upgrade

A kernel review (`review-kernel`) is required after this contract-input change, as for any kernel edit. Existing `$story` and `$s` commands still route to the PRD intent.
