# v1.16.3.0, A Scope the Model Would Pick Is a Missing Scope

Task Mode asks one question first "unless the request already contains enough direction". DeepSeek V4.1 Flash read a tracking plan that splits the build across three teams as enough direction and chose the scope itself in some runs of `STK-006`.

## What's New at a Glance

- **Enough direction never covers a scope the model would have to choose.** When a supplied source splits the work across teams, owners, surfaces or tickets and the request names none of them, the scope is missing and the first reply is the one question with no draft.
- **Both packagings carry it.** `references/task-mode.md` and the Project mirror `Product Owner - Templates - Task Mode - v0.307` gain the same line.
- **The kernel stays at v1.21.0.**
