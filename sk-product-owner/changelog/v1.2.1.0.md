# v1.2.1.0, One Reply Shape and One Question Round

A read of the Barter Deal Templates system set the patterns this release borrows. The 2026-10-08 Haiku 5.5 run showed why they were needed here. The 43 skill replies opened in ten different ways, three of them with a sentence before the path. 19 of them had bullets ending in a full stop. Three scenarios asked a second question on Turn 2 instead of drafting. Six of the seven Doc examples also failed the format gate they were meant to model. The release moves one patch step on the operator's choice.

## What's New at a Glance

- **One reply shape.** `assets/interactive-response-templates.md` Section 3 holds the Delivery Reply Shape: the path line first, the read-back line on the skill, the self-scan line, one quality line `Quality: {verdict} | Kind: {kind} | Energy: {energy}`, two or three sentences, `### Open items` and one closing line. It shows a wrong first line beside the right one and three worked replies. `AGENTS.md`, `SKILL.md`, Doc Mode, Story Mode, Interactive Mode, Quality Scoring and the kernel point there instead of describing the reply four ways.
- **Open items replace prose assumptions.** Every addition, assumption and safe default goes into a numbered item with its topic in bold, then a `- **Situation:**` bullet and a `- **Open:**` bullet with their text on the same line. No blank line sits inside or between items, because claude.ai joins a label left alone on its line to the line above. `None identified` stands alone when nothing applies.
- **One question round, then the draft.** Explicit commands still ask first. Once the user answers, the next reply drafts. A gap with a safe default is drafted and listed under Open items. Only a source conflict with no authority winner, a promised source still missing or a decision the user calls unsettled may hold the draft a second time.
- **The Doc quality line.** Doc's five checks, Source safety, Shape fit, ClickUp layout, Readability and Voice, now sit on the one quality line, each pass or attention. The old example with an em dash is gone.
- **Silent checks.** The Pre-Delivery Validation block in Interactive Mode is marked internal and never printed.
- **Doc examples pass the gate.** The Behavior Reference, Catalog, Guide, How It Works, Proposal and README examples lost their em-dash titles, headings, links and table cells and their prose semicolons, on both packagings.
- **Catalog entry headings may carry one em dash.** `### {Stable ID} — {Entry name}` and its `*   [{Stable ID} — {Entry name}](#{entry-anchor})` link are now a sanctioned shape, only inside a Catalog that carries its Index heading. A Catalog title, an H2 or a heading with no stable ID still takes a colon.
- **Checks.** The system validator and the shared Sync Loop validator gain the same Catalog grant, and three new fixtures prove it passes where it should and blocks everywhere else. A new `benchmark/gates/example_lint.py` runs every example and Project example mirror through the validator and reads every worked reply line by line, and its `--self-test` proves a broken example and a broken reply both fail. A new `benchmark/gates/run_gates.sh` runs the router and format fixtures, rule parity and the example lint in one command. Playbook 2.5.1.0: the Doc scenarios expect the quality line, and the disclosed-addition rule reads Open items.
- **The kernel moves to v1.2.1.**
