## [**1.9.0.0**] - 2026-09-25

A disclosed addition is no longer an invented requirement, and a clarification is saved and read back like any artifact. From the Claude Sonnet 5 medium playbook run of 2026-09-25, seven scenarios per packaging, on four operator decisions. Each decision is a rule change, so the skill moves to 1.9.0 and the Project kernel to v1.13.0.

> Scope: `SKILL.md`, `AGENTS.md`, the Doc Mode and Story Mode source pairs, the Project kernel, the playbook root and the Project scenario links. No routing, command or confidence behavior changed.

### What the run found

Every supplied fact reached every deliverable, and most failures were additions the user never supplied. `SKILL.md` asked for edge cases and assumptions in ALWAYS 8 and banned invented requirements in NEVER 4 with nothing between the two, so `STK-001` and `SIR-001` failed only on additions their replies named as additions. On the Project side the kernel sent the invention ban to Doc Mode knowledge alone, which a Task run never opens, and `PTK-001` and `PIR-001` added items their replies did not name. `SDK-002` made no tool call on turn 1 and exported no clarification, and the always-loaded `AGENTS.md` never said a clarification is saved. The Project runs had no Canvas panel, a case the kernel's render-first rule did not cover.

### What changed

On the operator's decisions:

- A disclosed addition is allowed. An edge case, assumption or other addition the user did not supply is allowed only when the chat response names it as an addition, so the user can strike it. One the response does not name is an invented requirement, and naming never makes invented evidence, a root cause or a platform detail acceptable. The rule sits in `SKILL.md` NEVER 4 with a pointer from ALWAYS 8, in NEVER 4 on both sides of the Doc Mode pair and in the source-of-truth bullet on both sides of the Story Mode pair. The playbook root names it as the one exception to the invented-fact rule
- The kernel's NEVER list carries the invention ban and the disclosure rule as item 6, so a Task run holds them without opening Doc Mode knowledge
- `AGENTS.md` Section 2 says a clarification is saved to `export/`, read back and reported like an artifact, under the `-clarification` name the Interactive Mode reference and the kernel already used, with `intake` in place of the artifact word when no artifact was resolved. The artifact then takes the next number in that lane and the clarification file stays untouched
- The kernel's render-first rule covers a session with no Canvas panel. The Deliverable Block comes first as one fenced block with no preamble about the missing panel, then the `Export-equivalent path:` line. A session that has the panel always uses it

### Versions

The Doc Mode pair moves to v0.110 and the Story Mode pair to v0.401, with their mirrors renamed and every live reference repointed. The playbook root moves to 1.0.0.2, and its kernel line citations and those in the Project Doc guide scenario follow the one-line shift. `SKILL.md` moves from 1.8.4 to 1.9.0, `description.json` from 1.8.0.0 to 1.9.0.0 and the kernel from v1.12.6 to v1.13.0.
