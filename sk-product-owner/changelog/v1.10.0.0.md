## [**1.10.0.0**] - 2026-09-25

A new Story exports under the `Story-` word, and a Story asked for with its task breakdown ships as one folder that links the Story and its tasks. Both are rule changes, so the skill moves to 1.10.0 and the Project kernel to v1.14.0.

> Scope: `AGENTS.md`, `SKILL.md`, the Story Mode, Interactive Mode and Task Templates source pairs, the Story template, the Interactive Response Templates, the Project kernel, both READMEs, the playbook root and its two Story shape scenarios. No routing, command or confidence behavior changed.

### Why

A new Story saved as `PRD-[description].md` while its Epic sibling saved as `Epic-[description].md`, so the artifact Story Mode produces most often was named for a document type the system otherwise calls a Story. A Story also could not ship with the tasks that deliver it. `AGENTS.md` read "write the story and break it into tasks" as independent multi-artifact actions and asked which one to make.

### What changed

- A new Story exports as `export/[###] - Story-[description].md`, and the clarification lane reads `{task|bug|doc|Story|Epic}`. `$prd` and `$p` stay as aliases, and a Story H1 still carries no `PRD -` prefix
- A new Story asked for with its task breakdown is one dependent deliverable. It routes to Story Mode in the Story shape, asks no question about which artifact to make, and saves as `export/[###] - Story-[description]/`, holding the Story and one `[###].[n] - task-[description].md` per task, `n` counting from 1 in the Story's task order. Two explicit artifact commands such as `$story $task` stay a conflict
- The Story lists its tasks in a `#### **Tasks**` block inside About, after References, each bullet linking the sibling task file. `## Scope` stays the Epic's section, so the kind check still holds
- Each task uses the Canonical Task template and names its Story in a new `**Story**` block between `**Epic**` and `**Parent task**`. Story Mode reads the Task Templates asset on demand for this, so the one-scaffold rule for the Story is unchanged
- A split the request names is authoritative. With none named, the one Story question asks for it. A clarification keeps the Story lane at the top of `export/`, and the folder takes the next number
- The skill reply lists every path in the bundle, Story first, each with its own read-back line, then one `HVR self-scan:` line for the whole bundle. The Project renders one Deliverable Block per file, each with its own `Export-equivalent path:`, then one self-scan line for the set

### Grounding

The Tasks block follows a team Story that lists its linked child tickets in an H4-bold block inside About, and the sibling links use the `(<file name.md>)` form a Feed v2.5 task already uses. The `**Story**` block follows the team's Chat tasks, which open by naming their Story, in the label, divider and bullet shape the Canonical Task template already gives `**Epic**`.

### Versions

The Story Mode pair moves to v0.402, the Interactive Mode pair to v0.405 and the Task Templates pair to v0.102, with their mirrors renamed and every live reference repointed. The kernel's declared delivery statement was resynced for the two lines that changed, and both kernel lines stayed in place, so no line the playbook cites moved. The playbook root moves to 1.0.0.4 and grades `Story` as the artifact word. The old playbook exports under `export/benchmark/` were removed before the next run, and the system README no longer names them. `SKILL.md` moves from 1.9.0 to 1.10.0, `description.json` from 1.9.0.0 to 1.10.0.0 and the kernel from v1.13.0 to v1.14.0. The kernel review by the operator is pending.
