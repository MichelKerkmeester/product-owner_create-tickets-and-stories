## [**1.8.2.0**] - 2026-09-18

A promised source no longer defers Doc intake. When a request says the notes are coming, the one consolidated question now asks for them together with every other unresolved field, such as authority, status and shape, rather than for the notes alone.

> Scope: `AGENTS.md`, the Doc Mode source pair, the Project kernel and the `SDK-001` and `PDK-001` scenarios. No routing, command, confidence or delivery behavior changed. The entry for 1.8.1 was never written, and that change is recorded in `SYNC.md` rather than repeated here.

### The rule the benchmark found missing

`SDK-001` and `PDK-001` open with `Document how the notification retry pipeline works for the support team. I will paste the engineering notes.` The request supplies purpose and audience, so the expected turn 1 is one question covering the source set, authority, status and shape. None of the four runs, Claude Sonnet 5 and GLM 5.3 Flash on both packagings, asked that question. Three asked for the notes with one other field at most, and one asked again for the purpose and audience the request had already supplied. The consolidation rule existed in both system prompts, and nothing in it covered a source the user promised but had not yet supplied. The operator decided turn 1 must ask every unresolved field at once even then. `AGENTS.md`, the kernel and `references/doc-mode.md` with its mirror now say so, and the Doc Mode pair moves to v0.107.

### The pass line now grades what the scenario expects

Both scenarios' expected signals and conversation chains required the consolidated question while the pass line did not, so a run that asked only for the notes could pass. The contract line, the Pass and Fail bullets and the summary table now require one consolidated question for every unresolved Doc field and fail a turn 1 that asks for the notes alone.
