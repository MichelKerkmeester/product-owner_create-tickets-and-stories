# v1.8.2.0, Promised Notes Join the First Question

A promised source no longer defers Doc intake. When a request says the notes are coming, the one consolidated question now asks for them together with every other unresolved field, such as authority, status and shape, rather than for the notes alone.

## Why This Release

`SDK-001` and `PDK-001` open with `Document how the notification retry pipeline works for the support team. I will paste the engineering notes.` The request supplies purpose and audience, so the expected turn 1 is one question covering the source set, authority, status and shape. Nothing in the consolidation rule covered a source the user promised but had not yet supplied. The operator decided turn 1 must ask every unresolved field at once even then.

## What's New at a Glance

- **A promised source stays in the consolidated question.** The question asks for the notes together with every other unresolved field, such as authority, status and shape, even when the user has promised the notes and not yet supplied them.
- **The Doc Mode pair moves to v0.107.** `AGENTS.md`, the kernel and `references/doc-mode.md` with its mirror now say that turn 1 asks every unresolved field at once, including a source the user promised but has not yet supplied.
- **The pass line matches the expected question.** Expected signals and conversation chains already required the consolidated question while the pass line did not, so a run that asked only for the notes could pass. The contract line, the Pass and Fail bullets and the summary table now require one consolidated question for every unresolved Doc field and fail a turn 1 that asks for the notes alone.
- **The 1.8.1 entry was never written.** That change is recorded in `SYNC.md` rather than repeated here.

## Upgrade

No migration required. No routing, command, confidence or delivery behavior changed.
